# 执行卡 018｜R03 统一 CLEAR 完成效果

批次：`B20260801-A`  
需求编号：`R03`  
更新时间：2026-08-01（UTC+8）  
状态：`WAITING_R01_R02_R04_R05_BASELINE`  
优先级：P2  
默认实施者：GPT  
Codex：仅做必要的跨模块状态和视觉集中验收

## 1. 目标

为已经正式完成的挑战、练习和探险任务建立统一 CLEAR 视觉语言。

固定定义：

- CLEAR 表示“本次正式任务已经完成”，不等于满分；
- 姐姐和弟弟的完成状态必须完全隔离；
- 只有正式完成状态才能显示，进度中、退出中、数据异常或仅有部分记录不得显示；
- 不遮挡分数、金币、按钮、错题信息和继续操作。

## 2. 已确认视觉方向

- 使用已确认的“印章 / 丝带式”视觉语言；
- 主色改为砖红色；
- 放置在任务模块正中间；
- 清楚可见但不过度遮挡；
- 首页任务卡、挑战结果页及其他确需显示完成状态的位置保持同一语义和构图规则。

正式实现前应把视觉样式固化为可复用组件，不允许每个模块各画一套近似效果。

## 3. 依赖

R03 最后实施，必须基于以下稳定结果：

- R01 已修复词汇探险入口；
- R04 已稳定奖励和挑战完成链路；
- R02 已稳定 `audioSpelling` 题型；
- R05 已稳定语法挑战确认行为。

R03 只能读取和呈现既有正式完成状态，不得反向重写上述业务逻辑。

## 4. 第一阶段：完成状态盘点

修改代码前，GPT 必须建立模块清单并逐项记录：

1. 模块名称与入口；
2. 首页卡片或结果页位置；
3. 正式完成状态的唯一来源；
4. 姐姐 / 弟弟隔离 Key 或 student 标识；
5. 进度中、退出、异常和历史记录的排除条件；
6. 是否应显示 CLEAR；
7. 是否存在重复状态来源需要收口。

至少盘点：

- 单词挑战；
- 语法挑战；
- 随堂练习；
- 词汇探险及其正式完成节点；
- 首页所有任务卡；
- 各挑战或练习结果页；
- 其他已经使用正式任务完成状态的学生端入口。

没有可靠完成来源的模块不得猜测并加 CLEAR。

## 5. GPT 实施任务

1. 读取最新业务基线和规定视口合同。
2. 完成状态盘点并在 PR 描述中保存映射。
3. 建立最小共享 CLEAR 组件或 helper，统一文本、砖红色、透明度、层级、位置和无障碍语义。
4. 默认位于模块中心，但根据卡片内容设置安全区，避免遮挡关键数据和按钮。
5. 组件应为展示层，不得把“满分”“获得金币”或 DOM 结果文本当成完成判断。
6. 切换姐姐 / 弟弟时重新读取当前学生状态，不得复用上一位学生的 CLEAR DOM 或缓存。
7. 状态降级、重置、任务重新开始或记录失效时，CLEAR 必须及时移除。
8. 动画如存在应短、轻量、可关闭，不阻碍操作；不得循环闪烁。
9. 对窄卡片、长标题和结果页分别检查遮挡与可读性。
10. 增加状态判断和账户隔离测试。

## 6. 禁止事项

- 不把 CLEAR 当作满分标志；
- 不根据金币数推断完成；
- 不根据“100 分”或结果页文案推断完成；
- 不为未完成、退出、暂停、异常或只有历史进度的任务显示；
- 不修改奖励、题型、尝试次数或正式完成写入逻辑；
- 不在每个页面复制一套难以统一维护的 CSS；
- 不扩大为首页整体重做。

## 7. GPT 可完成的验证

- 每个模块只读取已确认的完成来源；
- 姐姐完成不影响弟弟，反之亦然；
- 完成后显示，重置或切换状态后移除；
- CLEAR 不改变按钮点击、结果读取或键盘焦点；
- 组件层级不覆盖分数、金币、错题和主要操作；
- 砖红色在浅色与深色背景均有足够对比；
- 无未处理异常或重复组件残留。

## 8. Codex 仅做必要集中验收

若 GPT 环境无法完整覆盖，在整批 QA 阶段验证：

- iPad `1180 × 820` 首页与各结果页；
- 所有纳入模块的完成 / 未完成 / 退出 / 异常矩阵；
- 姐姐与弟弟来回切换；
- 不同分数和金币情况下 CLEAR 判断不漂移；
- 触控、按钮、滚动和结果信息无遮挡；
- 与 R01、R02、R04、R05 的候选合并版本无视觉或逻辑覆盖。

Codex 不重新选择视觉方案，只报告回归和遮挡证据。

## 9. 完成标准

- 完成来源清单已经记录；
- 所有纳入模块使用同一 CLEAR 组件和砖红色视觉；
- 组件位于模块中心且不遮挡关键内容；
- CLEAR 只代表正式完成；
- 姐姐与弟弟完全隔离；
- 未完成、退出和异常状态不会误标；
- 首页与结果页语义一致；
- 规定视口和触控操作无回归。
