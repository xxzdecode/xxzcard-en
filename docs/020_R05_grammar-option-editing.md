# 执行卡 020｜R05 语法挑战确认前允许修改选项

Codex：仅做必要的全部正式语法挑战集中回归

## 1. 目标

修复语法挑战“点击第一个选项后立即锁定，无法修改”的错误行为。

正确交互固定为：

```text
选择或调整答案
→ 在确认前可以继续修改
→ 点击“下一题”才正式确认并判分
→ 确认后冻结本题
→ 显示反馈并进入下一题
```

## 2. 已确认根因

当前 `challenge-locked` 模式在选项点击事件中立即执行：

```text
state.locked = true
→ 所有选项 disabled
→ nextButton 启用
→ 显示“答案已锁定，点击下一题判分”
```

实际判分发生在点击“下一题”调用 `submitChallenge()` 时，因此现有实现提前锁定，和正式确认时点不一致。

## 3. 范围

必须覆盖正式语法挑战中的：

- 单选；
- 多选；
- 排序；
- 分类；
- 复用同一交互骨架生成或维护的历史正式页面。

不得修改：

- 题目、正确答案和知识点映射；
- 分数计算和首次正确定义；
- 语法挑战历史、弱项汇总和奖励；
- 每日次数、完成状态和 CLEAR；
- 随堂练习允许检查、重试或显示答案的既有模式；
- 与本交互无关的页面视觉。

## 4. GPT 实施任务

1. 读取最新 `main`、正式语法挑战目录、生成骨架及相关测试。
2. 找到所有 `challenge-locked` 或等价模式的正式实现，不只修 2026-07-31 单页。
3. 移除“首次点击即 `state.locked = true`”的行为。
4. 单选：再次点击其他选项时替换当前选择；当前选项状态立即更新。
5. 多选：确认前可继续勾选和取消；只有满足可提交条件时启用下一题。
6. 排序：确认前可重新选择、取消和调整顺序；答案区同步更新。
7. 分类：确认前可重新选择词卡并改放目标区；不能因第一次放置永久锁死。
8. 点击“下一题”时原子化执行：防重复提交 → 锁定 → 判分 → 写记录 → 显示反馈。
9. 判分过程中和确认后所有选项必须禁用；快速双击下一题不得写入两次。
10. 保持原有反馈延时和下一题流程，除非根因要求最小调整。
11. 更新正式生成骨架，确保未来新语法挑战不会再次带入旧错误。
12. 如历史正式页面包含复制代码，按统一策略批量修复并逐页验证；不得只改最新页面。
13. 更新 QA helper，使自动测试能够选择、改选、确认并检查锁定状态。

## 5. 按题型验收矩阵

### 单选

- 点击 A，再点击 B，最终选中 B；
- A 不再保持选中；
- 未点下一题前不判分、不写历史；
- 点下一题后不能再改。

### 多选

- 可以连续选择多个；
- 可以取消已选项；
- 修改后最终选择用于判分；
- 确认后只写一次结果。

### 排序

- 可取消已选词块；
- 可重新按新顺序选择；
- 答案区实时反映最终顺序；
- 确认前不判分。

### 分类

- 可重新选择已放置或未放置词卡；
- 可把词卡从一个目标改到另一个目标；
- 只有最终完整分配用于判分；
- 确认后冻结全部目标和词卡。
