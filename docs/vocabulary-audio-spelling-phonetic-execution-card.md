## 1. 目标

完善“纯听力写单词”题型：在学生听音并输入单词时，同时显示该单词已有的音标，减少音频含混、设备扬声器差异或环境噪音造成的误判。

本批必须同时覆盖：

1. 单词探险中的纯听力写单词；
2. 单词挑战中的纯听力写单词。

两处表现、数据读取、缺失处理和样式必须一致，不能只修其中一个入口。

---

## 2. 范围边界

本批只处理当前正式题型 `audioSpelling`。

不得借本次修改：

- 恢复、重启或重新定义旧的 `audioToWord`、`phoneticToWord` 等已停用题型；
- 修改题型抽取比例、题目顺序、挑战题数、判分规则或重试规则；
- 修改单词数据结构或新增音标数据库字段；
- 修改发音音频、语音提供方、播放速度或自动播放策略；
- 修改金币、挑战结算、iPad 入口稳定性；
- 实现 CLEAR 完成效果；
- 重做单词卡或其他题型界面。

若发现音标数据本身缺失，只做安全降级并记录，不得在本批批量生成或猜测音标。

## 5. 功能要求

### 5.1 显示条件

仅当当前正式题型为 `audioSpelling` 时显示音标。

其他题型不得因本次修改额外显示音标，除非其原有设计本来就显示。

显示判断必须依据题型状态，不得用按钮文案、DOM 文本或页面位置猜测题型。

### 5.2 数据来源

按当前项目已使用的卡片音标字段读取，优先使用题目当前 card / target card 上的正式音标值。

要求：

- 不调用外部接口临时生成；
- 不通过单词文本自动拼接伪音标；
- 不写回数据库；
- 不改变原始音标内容；
- 保留现有斜杠、重音符号、长音符号和英美标注格式。

需要兼容首尾空格、空字符串、`null`、`undefined` 等情况。

### 5.3 缺失降级

当前单词没有有效音标时：

- 不显示空的音标占位；
- 不显示 `undefined`、`null`、破折号或“暂无音标”；
- 不影响音频播放、输入框、提交、判分和下一题；
- 控制台不得产生未捕获异常。

### 5.4 界面位置

推荐顺序：

```text
题目提示
→ 播放音频按钮
→ 音标
→ 单词输入框
→ 提交或下一步操作
```

音标应与音频按钮形成明显关联，但不能挤压输入框或主要操作。

不允许：

- 把音标放进输入框 placeholder；
- 把音标做成可编辑内容；
- 遮挡播放按钮、输入框、反馈层或底部操作按钮；
- 使用过小、过淡或低对比度文字；
- 因音标长度导致横向溢出。

长音标允许自然换行，但同一道题不应因此出现明显布局跳动或操作区域被推出正式视口。

### 5.5 一致性

探险与挑战必须共用同一显示规则：

- 字号层级一致；
- 间距一致；
- 缺失音标时行为一致；
- 切题、重试、答错反馈后刷新行为一致；
- 同一单词在两个入口显示的音标文本一致。

若两个页面容器不同，可分别做轻量布局适配，但视觉语义必须一致。

## 6. 状态更新要求

切换到下一题时必须同步更新音标，不能残留上一题内容。

以下场景逐一检查：

1. 第一题直接进入 `audioSpelling`；
2. 从其他题型切换到 `audioSpelling`；
3. 从 `audioSpelling` 切换到其他题型；
4. 连续两道 `audioSpelling`；
5. 当前词有音标，下一词无音标；
6. 当前词无音标，下一词有音标；
7. 答错后重试或显示反馈；
8. 挑战完成前的最后一道题。

离开 `audioSpelling` 时，音标 DOM 必须隐藏或清空，不能在其他题型中残留。

---

## 7. 可访问性与输入体验

- 音标使用正常文本节点，不能只放在 CSS `content` 中；
- 不应抢占输入框焦点；
- 重新播放音频后，输入框焦点策略保持现状；
- 软键盘弹出时，音标和输入框仍应可见；
- 屏幕阅读器不应把装饰符号重复朗读多次；
- 若现有页面已使用 ARIA 结构，沿用现有模式，不新增无意义 live region。

本功能正式验收基准：

- iPad Air 11 英寸横屏：`1180 × 820` CSS 视口。

仅当项目现有词汇探险合同明确要求手机端时，再补充：

- iPhone 16 竖屏：`393 × 852` CSS 视口。

不得自行扩大到其他设备矩阵。

验收时至少覆盖：

- 短音标；
- 带重音符号的音标；
- 较长音标；
- 无音标；
- iPad 软键盘弹出后的输入状态；
- 探险与挑战各一轮。

## 9. 自动测试要求

至少补充或更新测试，验证：

1. `audioSpelling` 且有音标时正确显示；
2. `audioSpelling` 且无音标时不渲染空占位；
3. 非 `audioSpelling` 题型不因本次修改显示音标；
4. 切换题目后不会残留上一题音标；
5. 探险和挑战读取同一正式字段；
6. 音标展示不改变答案判定；
7. 缺失字段不会抛异常。

运行仓库现有相关测试、lint 和必要的浏览器测试。不得通过删除断言、跳过测试或放宽题型判断来让测试通过。
