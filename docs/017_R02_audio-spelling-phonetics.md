# 执行卡 017｜R02 纯听力写单词显示音标

批次：`B20260801-A`  
需求编号：`R02`  
更新时间：2026-08-01（UTC+8）  
状态：`WAITING_R04_BASELINE`  
优先级：P1  
默认实施者：GPT  
Codex：仅做必要的题型、软键盘和视口集中验收

## 1. 目标

在当前正式题型 `audioSpelling` 中显示单词已有的正式音标，同时覆盖：

- 单词探险；
- 单词挑战。

两处必须使用同一数据来源、显示规则和缺失降级。

## 2. 依赖

R02 必须在 R04 奖励结算修复形成稳定基线后实施，因为两项可能同时修改 `js/vocabularyAdventureChallenge.js`。不得从旧基线并行重写挑战核心文件。

## 3. 范围

只处理 `audioSpelling` 的音标展示。

不得修改：

- 题型比例、顺序、题数或重试规则；
- 单词数据结构或数据库字段；
- 发音提供方、播放速度或自动播放策略；
- 奖励、挑战次数或完成状态；
- 已停用题型；
- CLEAR 视觉和首页布局。

## 4. 数据规则

- 使用当前 card / target card 已有的正式音标字段；
- 不调用外部接口；
- 不自动拼写或猜测音标；
- 不写回数据库；
- 保留原有斜杠、重音、长音和英美标注；
- 空字符串、`null`、`undefined` 或只有空格时安全隐藏；
- 无音标不得显示占位符、“暂无音标”或异常文本。

## 5. GPT 实施任务

1. 读取 R04 合并后的最新基线。
2. 确认探险与挑战当前 `audioSpelling` 的 card 来源和正式音标字段。
3. 优先提取最小共享 helper，避免两处出现不同规则；不得为一个字段大规模重构播放器。
4. 推荐顺序：题目提示 → 音频按钮 → 音标 → 输入框 → 主要操作。
5. 音标必须是正常文本节点，不放进 placeholder 或 CSS `content`。
6. 音标不得抢占输入焦点，不得遮挡音频、输入框、反馈和底部操作。
7. 切题、重试、答错反馈和离开 `audioSpelling` 时必须更新、隐藏或清空音标。
8. 有音标到无音标、无音标到有音标、连续两道音标题都不得残留上一题内容。
9. 增加与题型状态和缺失字段相称的测试。

## 6. 重点文件

预计包括：

- `js/vocabularyAdventurePlayer.js`
- `js/vocabularyAdventureChallenge.js`
- `js/vocabularyQuestionTypesRepeatBootstrap.js`

- 现有音标读取或规范化 helper

## 7. GPT 可完成的验证

- `audioSpelling` 有音标时正确显示；
- 无音标时不渲染空占位；
- 非 `audioSpelling` 不新增音标；
- 探险和挑战读取同一正式字段；
- 切题和重试无残留；
- 音标展示不改变答案判定；
- 缺失字段不抛异常。

## 8. Codex 仅做必要集中验收

如当前 GPT 环境不能可靠覆盖，集中 QA 阶段验证：

- iPad `1180 × 820`；
- 短音标、长音标、带重音音标和无音标；
- 软键盘弹出后音标与输入框仍可见；
- 探险与挑战各完成一轮；
- 音频、输入、判分、反馈和奖励链路无回归。

Codex 不改题型设计，只报告失败证据。

## 9. 完成标准

- 探险和挑战的 `audioSpelling` 均显示正式音标；
- 两处字段、样式、缺失处理一致；
- 无音标安全隐藏；
- 非目标题型无新增显示；
- 切题无残留；
- iPad 正式视口无遮挡、溢出或明显跳动；
- 音频、输入、判分、奖励和挑战完成状态无回归。
