## 4. 执行顺序与依赖

正式顺序：

```text
R01 → R05 → R04 → R02 → R03 → GPT 整批审核 → 单次集中 QA → GPT 修复 → 最终合并审核
```

原因：

1. R01 是 iPad 阻断问题，优先恢复入口可靠性。
2. R05 与词汇链路相对独立，可在前期完成，避免继续生成错误交互的语法挑战页面。
3. R04 必须早于 R02，因为两项可能同时修改 `js/vocabularyAdventureChallenge.js`。
4. R03 会读取多个挑战、练习和探险的完成状态，必须等待业务状态和交互逻辑稳定后最后实现。
5. 不允许 R02、R04 同时从旧基线各自重写挑战核心文件；后一项必须基于前一项已合并或已确认的新基线。

## 5. GPT 与 Codex 分工

### GPT 默认负责

- 读取最新规则和代码；
- 根因分析与方案确认；
- HTML、CSS、JavaScript、规则和测试代码修改；
- 创建分支、提交和 Draft PR；
- 根据执行卡审核 diff；
- 修复集中 QA 发现的问题；
- 给出最终合并顺序。

### Codex 仅在必要时负责

- Playwright WebKit 和规定视口测试；
- 旧 Service Worker、旧缓存、离线和失败重试环境；
- 需要完整依赖或 CI 环境的自动测试；
- 候选合并版本的跨模块回归；
- 输出 QA 报告，不重新设计或擅自扩展功能。

调用 Codex 前必须说明 GPT 无法可靠完成的具体环节。能够由 GPT 当前工具完成的任务不得默认转交 Codex。
