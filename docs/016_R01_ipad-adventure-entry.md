## 1. 目标

修复 iPad 横屏点击“词汇探险”后无法打开、而电脑端正常的问题，并使入口在加载、失败和重试期间始终有明确反馈。

## 2. 范围

本卡只处理：

- 首页词汇探险入口；
- 相关懒加载链路；
- 必要的 Service Worker / 运行时缓存策略；
- 加载状态、失败提示、重试和重复点击保护；
- 与入口可靠性直接相关的自动测试。

不得处理：

- 金币结算；
- 纯听力音标；
- CLEAR 视觉；
- 挑战题型、题数或每日次数；
- 首页整体重做。

## 3. 已知事实与待验证项

已知：

- 首页入口调用 `openVocabularyAdventure()`；
- 词汇探险通过 `js/lazyFeatures.js` 动态加载核心、播放器、复习及题型相关脚本；
- Service Worker 与动态依赖的版本、缓存和旧页面兼容需要一起核对；
- 电脑端正常不能证明 iPad Safari、主屏幕 Web App 或旧缓存场景正常。

以下只是假设，必须用实际日志和请求证据确认：

- iPad 被旧 Service Worker 控制；
- 动态脚本缺失于可靠缓存；
- 懒加载失败后 Promise 或代理未复位；
- 多次点击产生重复加载或竞态；
- 实际已经开始加载，但页面没有反馈，看起来像“点不开”。

## 4. GPT 实施任务

1. 读取最新 `main`、`AGENTS.md`、`PROJECT_INDEX.md`、`PROJECT_STATE.md` 和设备视口合同。
2. 跟踪入口点击到真实播放器打开的完整调用链。
3. 检查所有动态依赖路径、加载顺序、失败分支和重复加载保护。
4. 实现单一有效加载 Promise；失败后必须清理状态并允许重试。
5. 点击后立即显示页面内加载反馈，不得静默等待。
6. 加载失败时显示明确错误和可点击重试入口，不只使用 `alert()`。
7. 快速重复点击不得插入多套脚本或打开多个播放器。
8. 若修改缓存清单或策略，升级 Service Worker 缓存版本并清理旧缓存。
9. 不得通过关闭 Service Worker、取消缓存或永久同步加载全部模块规避问题。
10. 增加与根因相称的单元或浏览器测试。

## 8. 完成标准

- iPad 正式视口单击一次可进入探险；
- 点击后立即出现加载反馈；

- 多次点击不会重复加载或多开播放器；
- 旧缓存升级后不出现永久空白或永久点不开；
- 已缓存成功后离线可重新打开；
- 其他懒加载功能无回归；
- 控制台无未处理异常；
- 真实 iPad Safari 最后完成人工确认。
