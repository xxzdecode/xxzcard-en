# 系统单词总库、引用单词本与分类关系约定

更新时间：2026-07-30 22:58（UTC+8）
状态：正式架构约定

## 1. 三层职责必须分开

### 系统单词总库

- 正式位置：Supabase `kv_store.main.masterCards`。
- 每个标准化英文 `wordKey` 只保存一张完整正式卡。
- 单词卡只保存单词资料，不保存 `category`、`categories`、`categoryId`、`categoryName` 等分类属性。
- 同一个词可被任意数量的单词本和分类复用。

### 单词本

- 单词本只是调用总库单词的集合。
- 持久化内容使用 `cardRefs` / `wordKey`，不重复保存完整卡片。
- 单词本可以保存通用元数据，例如稳定 `id`、显示 `name`、日期、用途、分享对象、归档状态。
- 单词本本身不保存 `categoryId` 或 `categoryName`。名称可以叫“颜色”“家庭成员”等，但名称只是显示名称，不是单词属性。
- 删除或归档单词本不得删除 `masterCards` 中的词条。

示例：

```json
{
  "id": "book-colours",
  "name": "颜色",
  "bookType": "reference",
  "cardRefs": [
    { "wordKey": "red" },
    { "wordKey": "blue" },
    { "wordKey": "orange" }
  ]
}
```

### 分类关系

- 分类范围和关系继续独立维护，不写入单词卡，也不写死在单词本导入 JSON 中。
- 当前分类骨架文件为 `data/vocabularyCategories.json`。
- 附件分类表只是第一版骨架，不是不可调整的最终名单。
- 后续可以增加、删除、拆分、合并、改名或调整分类中的词；不需要修改总库卡片。
- 一个词可以同时存在于多个分类关系中。

## 2. 导入 JSON 的正式职责

导入包只负责两件事：

1. 对总库执行必要的新建或增量补充；
2. 创建或更新一个引用式单词本。

导入包不得承担永久分类表的职责，因此不应包含：

```json
{
  "categoryId": "colours",
  "categoryName": "颜色"
}
```

### 已有且资料完全一致的词

只写引用：

```json
{ "wordKey": "red" }
```

不得再次复制完整 `red` 卡片。

### 总库不存在的词

在 `masterPatch.create` 中提供完整卡片，同时在单词本中写引用。

### 总库已有但需要补充资料的词

只提交差异，不提交整张卡。正式支持方向：

- `setIfEmpty`：只补空字段；
- `appendUnique`：为例句、搭配、词形、同义词、词族等数组去重追加；
- 非空字段冲突进入预览，不自动覆盖。

### 仅当前教学场景需要不同展示

默认不要制造第二张卡。确有必要时可以在引用层保存最小 `overrides`，但只有明确教学需求才使用；普通分类不需要覆盖。

## 3. 导入器必须实现的安全规则

- 先审计总库，再生成导入包。
- 预览中分别显示：直接复用、新建、补空、去重追加、冲突、当前单词本引用。
- 导入必须幂等；同一文件重复导入不得制造重复词或重复例句。
- 默认禁止覆盖总库已有非空字段。
- 冲突必须停在人工确认步骤。
- 导入完成后，单词本持久化只保留引用；网页运行时从 `masterCards` 还原卡片。
