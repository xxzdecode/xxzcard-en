# 系统单词总库、引用单词本与分类关系约定

更新时间：2026-07-31 00:22（UTC+8）
状态：正式架构约定

## 1. 三层职责必须分开

### 系统单词总库

- 正式位置：Supabase `kv_store.main.masterCards`。
- 每个标准化英文 `wordKey` 只保存一张完整正式卡。
- 单词卡只保存单词资料，不保存 `category`、`categories`、`categoryId`、`categoryName` 等分类属性。
- 同一个词可被任意数量的单词本和分类复用。

### 单词本

- 单词本只是调用总库单词的集合。
- 持久化内容使用 `cardRefs` / `wordKey`，不重复保存完整卡片。
- 单词本可以保存通用元数据，例如稳定 `id`、显示 `name`、日期、用途、分享对象、归档状态。
- 单词本本身不保存 `categoryId` 或 `categoryName`。名称可以叫“颜色”“人物”等，但名称只是显示名称，不是单词属性。
- 删除或归档单词本不得删除 `masterCards` 中的词条。

示例：

```json
{
  "id": "book-colours",
  "name": "颜色",
  "bookType": "reference",
  "cardRefs": [
    { "wordKey": "red" },
    { "wordKey": "blue" },
    { "wordKey": "orange" }
  ]
}
```

### 分类关系

- 分类范围和关系继续独立维护，不写入单词卡，也不写死在单词本导入 JSON 中。
- 当前分类骨架文件为 `data/vocabularyCategories.json`。
- 附件分类表只是第一版骨架，不是不可调整的最终名单。
- 后续可以增加、删除、拆分、合并、改名或调整分类中的词；不需要修改总库卡片。
- 一个词可以同时存在于多个分类关系中。

## 2. 导入 JSON 的正式职责

导入包只负责两件事：

1. 对总库执行必要的新建或增量补充；
2. 创建或更新一个引用式单词本。

导入包不得承担永久分类表的职责，因此不应包含：

```json
{
  "categoryId": "colours",
  "categoryName": "颜色"
}
```

### 已有且资料完全一致的词

只写引用：

```json
{ "wordKey": "red" }
```

不得再次复制完整 `red` 卡片。

### 总库不存在的词

在 `masterPatch.create` 中提供完整卡片，同时在单词本中写引用。

### 总库已有但需要补充资料的词

只提交差异，不提交整张卡。正式支持方向：

- `setIfEmpty`：只补空字段；
- `appendUnique`：为例句、搭配、词形、同义词、词族等数组去重追加；
- 非空字段冲突进入预览，不自动覆盖。

### 仅当前教学场景需要不同展示

默认不要制造第二张卡。只有同形词或明确的当前单词本专用展示确实无法安全共用总库卡时，才允许在引用层保存最小 `overrides`。

正式案例：

- 总库 `wordKey: miss` 保存动词 `miss`，释义“错过”；
- “人物”单词本引用同一个 `wordKey: miss`，通过 `overrides` 显示称谓 `Miss`，释义“小姐；女士”；
- 覆盖只作用于该单词本运行时卡片，绝不修改总库 `miss`。

普通分类差异、释义补充或例句增加不得使用覆盖。详细格式见 `docs/reference-wordbook-import-format.md`。

## 3. 导入器必须实现的安全规则

- 先审计总库，再生成导入包。
- 预览中分别显示：直接复用、新建、补空、去重追加、冲突、当前单词本引用。
- 导入必须幂等；同一文件重复导入不得制造重复词或重复例句。
- 默认禁止覆盖总库已有非空字段。
- 冲突必须停在人工确认步骤。
- 导入完成后，单词本持久化只保留引用；网页运行时从 `masterCards` 还原卡片。
- `cardRefs[].overrides` 必须随引用持久化，并在运行时还原；不得反向写入总库。

## 4. 网页读取、查看与学习写入边界

单词卡页面必须区分“只读查看”和“会写学习进度的学习模式”。

### 单词本列表与只读查看

- 页面进入时先使用当前内存数据或本地 Supabase 镜像立即渲染，不等待网络请求后才显示。
- 进入单词卡页面后，在后台读取最新 `kv_store.main`；读取成功时替换当前 `appData` 并自动重新渲染列表。
- 因此同一页面停留期间新增的云端单词本可以在后台刷新后出现，不要求用户先等待阻塞式加载。
- 打开单词本详情、查看具体单词卡、字典搜索结果和单词链接时，先使用本地学习记录立即显示；学习记录随后在后台更新。
- 老师端列表不得为了显示全部学习统计而对所有单词本执行阻塞式 `Promise.all` 云端读取。

### 会写学习进度的模式

- “全部学习”“随机模式”“生词池”等可能写入 `known / unknown` 的流程，开始前必须读取该学生、该单词本的最新云端记录。
- 本地镜像不得直接作为正式写入基线，避免旧设备记录覆盖其他设备上的新进度。
- 加速查看不能以牺牲学习记录一致性为代价。

### 资源缓存

- 单词卡相关脚本可以在首页加载期间后台预热，并纳入 Service Worker 应用壳缓存。
- 预热失败不得阻止首页和其他功能使用；实际入口仍保留按需加载兜底。
