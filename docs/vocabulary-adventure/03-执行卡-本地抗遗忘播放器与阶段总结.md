## 4. 核心实现原则

### 4.1 不复用旧 review 的整轮控制器

现有 `js/review.js` 可以提供参考或无副作用辅助能力，但不得直接启动旧整轮：

```text
buildReviewSteps()
renderReviewStep()
nextReviewStep()
finishReviewRound()
saveReviewComplete()
markCardUnknown()
```

原因：

- 旧流程维护自己的轮次和错题状态；
- 会写旧 `known / unknown`；
- 不认识探险 session、plan item 和 cursor；
- 不能保证逐目标词保存；
- 不能保证保存失败时 UI 不前进；
- 不能保证执行卡 1 的 D / H / F 和间隔更新。

新抗遗忘播放器必须继续沿用：

```text
纯函数准备完整状态
→ 完整状态保存成功
→ UI 前进
```

### 4.2 允许复用的能力

可以复用或提取：

- 唯一英文选项生成；
- 唯一中文选项生成；
- 音标读取；
- 缺字母构题；
- 字母排序控制器；
- 听音拼写构题；
- 搭配提取；
- 例句提取；
- 句子排序构题；
- 发音；
- 完整卡片渲染；
- HTML escaping；
- 卡片字段标准化。

若现有函数被全局状态、DOM 或 `Math.random()` 强绑定：

- 不得直接硬调用；
- 应提取为无副作用辅助函数；
- 保留旧调用方行为；
- 为新函数增加测试；
- 不得重构整个 `questionTypes.js` 或 `review.js`。

### 4.3 结果写入仍必须原子

每个 review 目标词完成时，必须一次准备：

- word state；
- plan item；
- taskType；
- result；
- status；
- review reason 保留；
- cursor；
- phase；
- completed；
- `lastTaskType`；
- `lastReviewedAt`；
- `nextDueAt`；
- interval；
- reviewCount；
- 当日汇总需要的轻量结果信息。

不得先局部改对象、保存后再补 cursor。

## 6. 题型类别

### 6.1 基础意义类

```text
visualMatch
wordToMeaning
meaningToWord
audioToWord
```

用于确认：

```text
声音 / 英文形式 / 基本意思
```

这类题可以直接决定 D / H / F。

### 6.2 词形类

```text
phoneticToWord
missingLetters
letterOrder
audioSpelling
```

用于进一步加强：

- 音标；
- 拼写；
- 字母顺序；
- 听音拼写。

这类题可以决定 D / H / F，但题型不可用时必须安全回退到基础意义类。

### 6.3 使用拓展类

```text
collocationCloze
exampleCloze
sentenceOrder
```

使用题答错时不得立即判 F。

必须进入：

```text
同词基础意义确认
```

只有基础意义确认也错误才是 F。

## 7. 按状态与原因分题

必须先读取 plan item 的 review reason 和当前 word state。

原因建议沿用执行卡 1 的真实字段，不另造第二套来源。

### 7.1 `challengePending`

挑战错词只能表示：

```text
下一次探险待复查
```

本卡虽然不负责写入 challenge pending，但若状态中已有该标记，必须：

- 优先基础意义题；
- 禁止直接使用搭配、例句、句子排序；
- 只由本次基础检索改变 D / H / F；
- 完成后按执行卡 1 既有规则清理对应 pending 标记。

允许题型：

```text
wordToMeaning
meaningToWord
audioToWord
visualMatch
```

### 7.2 F

F 词优先确认最基础连接。

优先顺序：

```text
audioToWord
wordToMeaning
meaningToWord
visualMatch
missingLetters
letterOrder
```

限制：

- 不得直接分配使用拓展题；
- 不得优先分配高负担听写；
- 第一次正确可为 D；
- 第一次错后提示；
- 提示后正确为 H；
- 再错为 F。

### 7.3 H

H 词重点从提示依赖过渡到独立提取。

候选：

```text
audioToWord
phoneticToWord
missingLetters
letterOrder
wordToMeaning
meaningToWord
visualMatch
```

在字段足够且历史任务不重复时，可以少量使用：

```text
audioSpelling
```

### 7.4 到期 D / 普通 due

候选可以更广：

```text
wordToMeaning
meaningToWord
audioToWord
visualMatch
phoneticToWord
missingLetters
letterOrder
audioSpelling
collocationCloze
exampleCloze
sentenceOrder
```

使用拓展题必须满足字段和二次确认条件。

### 7.5 severe overdue

严重逾期不得直接从高难使用题开始。

优先：

```text
基础意义
→ 词形
→ 使用拓展
```

本次每个 plan item 仍只执行一个正式题；这里表示选题优先级，不是同词连续做三题。

### 7.6 stable

稳定抽查可以使用更广题型，但必须避免：

- 连续多次同一题型；
- 使用题字段不足；
- 仅凭翻翻乐升级间隔；
- 因翻翻乐操作失误直接 F。

## 8. 确定性选题

执行卡 2 已要求摸底题确定性。本卡继续使用稳定 seed。

seed 至少包含：

```text
session date
user key
wordKey
plan index
phase = review
review reason
```

不得使用 `Math.random()` 决定：

- 正式题型；
- 正确答案位置；
- 正式干扰项；
- 缺字母位置；
- 字母顺序；
- 句子词块顺序；
- 翻翻乐卡片顺序。

允许将现有随机辅助提取为：

```js
createSeededRandom(seed)
seededShuffle(items, seed)
seededPick(items, seed)
```

刷新后必须得到同一题：

- 同一题型；
- 同一选项；
- 同一正确答案位置；
- 同一缺字；
- 同一排列顺序。

不能因为刷新更换题目来逃避错误。

## 9. 题型可用性和安全回退

### 9.1 通用要求

每个题型必须先 `isAvailable()`。

构题失败不得：

- 抛出未捕获错误；
- 写入结果；
- 前进 cursor；
- 用空答案继续；
- 直接判 F。

### 9.2 回退层级

固定回退：

```text
同类别其他题型
→ 基础意义题
→ 最低 2 选项基础题
→ 安全停止并报告当前 wordKey
```

选项数量继续沿用：

```text
4 → 3 → 2
```

不足 2 个唯一有效选项：

- 停留当前 plan item；
- 不保存错误结果；
- 显示对学生友好的“这张卡暂时不能出题”；
- 控制台记录 wordKey、题型和缺失字段；
- 测试必须覆盖。

### 9.3 可用字段

只能使用现有单词卡字段。

不得新增或假设：

- 新图片 URL 字段；
- 新音频 URL 字段；
- 新 usage level；
- 新日志表；
- 新题库表。

## 10. 视觉—英文翻翻乐

### 10.1 新玩法边界

新翻翻乐只用于探险 review。

不得改变旧 review 中现有英文—中文翻翻乐。

### 10.2 配对内容

优先：

```text
视觉卡 ↔ 英文单词卡
```

视觉降级：

```text
现有可用视觉
→ card.emoji
→ 中文意义
```

若代码中已有正式图片解析接口，可读取；若没有，不得为本卡引入新图片系统。

### 10.3 单 plan item 原则

一个 review plan item 只对应一个正式目标词。

翻翻乐可显示：

```text
目标词 + 2～3 个干扰词
```

完成整个小棋盘后：

- 只更新当前目标词；
- 干扰词仅为操作素材；
- 不修改干扰词状态；
- 不增加干扰词 reviewCount；
- 不移动其他 plan item。

### 10.4 结果证据边界

翻翻乐主要是强化，不是强证据。

建议判定：

- 无错误完成：D；
- 有一次错误配对后完成：H；
- 多次错误或超出安全阈值：进入同词基础意义确认；
- 基础意义正确：H；
- 基础意义错误：F。

不得仅凭翻翻乐无误就跨越多个间隔等级。

间隔仍只调用统一算法一次。

### 10.5 可访问性

要求：

- 卡片可键盘操作；
- 正反面有可读文本；
- 不只依赖颜色；
- 配对成功与失败有文字反馈；
- 按钮最小高度 44px；
- iPad 横屏同屏完成；
- 不出现棋盘与底部反馈条重叠。

## 11. 普通题的一次提示

基础意义和词形题继续使用：

```text
第一次正确 → D
第一次错误 → 一次轻提示，不保存
提示后正确 → H
提示后再次错误 → F
```

提示按题型选择：

- 重播发音；
- 显示首字母；
- 减少一个干扰项；
- 显示 emoji；
- 高亮音标；
- 固定一个正确字母位置；
- 重新排列可见项，但不得改变答案内容。

限制：

- 每题最多一次提示；
- 不允许第三次正式作答；
- 第一次错不运行间隔算法；
- 第一次错不增加 reviewCount；
- 提示状态必须在刷新策略中明确。

推荐：

```text
提示前尚未产生正式结果
```

若页面刷新：

- 允许重新进入同一题；
- 不保存第一次错误；
- 不能产生重复正式结果。

若实现提示状态持久化，必须作为 session 当前 UI 轻量状态，不得另建数据库结构；本卡不强制持久化第一次错误。

- 重置间隔；
- 标陌生；
- 显示最终完整错题卡；
- 保存正式结果。

必须生成同一个词的基础意义确认。

优先：

```text
wordToMeaning
meaningToWord
audioToWord
```

基础确认题必须确定性，且不能再次生成使用题。

### 12.3 基础意义确认正确

结果：

```text
H
```

含义：

```text
本次 usage weak
不把单词判为陌生
当前间隔保持
不得升级间隔
```

允许在当前 plan item 保存轻量标记：

```js
outcomeDetail: 'usageWeak'
```

或复用现有等价字段。

限制：

- 不得在 word state 新增长期 usage 等级；
- 不得建立 usage 历史日志；
- 不得改变单词卡结构。

### 12.4 基础意义确认错误

结果：

```text
F
```

处理：

- 间隔回到 1 天；
- 显示完整卡；
- 保存后前进。

### 12.5 保存原子性

使用题错误后的确认阶段，在正式结果出现前不得保存半成品。

最终一次准备：

```text
word state + plan item + cursor + summary
```

只运行一次间隔算法。

## 13. 结果与间隔

继续使用统一规则：

```text

```

后续抗遗忘：

```text

```

要求：

- 不在 UI 文件计算日期；
- 只调用执行卡 1 核心函数；

- challenge pending 的清理遵循当前核心状态规则；
- 不影响 screening 已有结果。
