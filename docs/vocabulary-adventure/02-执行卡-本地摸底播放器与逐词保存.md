## 1. 本轮开始前先补齐执行卡 1 的一个边界

该项属于执行卡 1 的计划生成闭环，不是执行卡 3 功能。

### 1.1 当前边界问题

当前实现把 `stable` 稳定抽查词直接放入统一 `review` 池。这样在：

```text
未摸底词充足
+ 真正到期或待复查词只有 4 个
+ 稳定词很多
```

时，可能生成：

```text
20 screening + 10 review
```

其中 6 个是稳定抽查词。

正式规则要求此时优先使用更多未摸底词，结果应为：

```text
26 screening + 4 urgent review
```

稳定抽查只能在“未摸底词 + 真正待复查词”合计仍不足 30 时最后补位。

### 1.2 必须修正的选择顺序

将抗遗忘候选区分为：

```text
urgent review:
challenge
→ F
→ H
→ severe overdue
→ due

stable review:
stable
```

正常阶段生成顺序固定为：

1. 先取最多 20 个 screening；
2. 再取最多 10 个 urgent review；
3. 总数不足 30 时，先用额外 screening 补位；
4. 仍不足时，用额外 urgent review 补位；
5. 只有前两类全部取完后仍不足 30，才用 stable review 补位；
6. 总池仍不足时，只返回全部唯一可用词。

必须保留：

```text
screening 全部在前
→ review 全部在后
```

### 1.3 新增回归测试

至少增加：

```text
screening 30
urgent review 4
stable 20
→ 26 screening + 4 urgent review + 0 stable
```

以及：

```text
screening 3
urgent review 5
stable 30
→ 总数 30，stable 只补最后缺口
```

不得改变挑战、F、H、逾期和到期的既有优先级。

## 2. 本轮唯一产品目标

建立一个独立的“探险摸底播放器”，只处理 session 中的：

```text
phase = screening
status = pending
```

完整流程：

```text
读取或创建当天 session
→ 定位当前 screening 计划项
→ 生成一种基础检索题
→ 第一次作答
→ 正确：D
→ 错误：给一次轻提示
→ 提示后正确：H
→ 提示后仍错误：F
→ 写入单词状态和计划项
→ 保存整个规范化探险状态
→ 保存成功后进入下一词
→ 中途退出后可从已保存 cursor 恢复
```

本轮只完成摸底阶段。

若 cursor 已进入：

```text
phase = review
```

只显示“第一站摸底已完成，第二站尚未接入”的本地阶段边界页，不生成任何抗遗忘题，不修改该 review 项。

## 5. 三种基础摸底题

题型 ID 固定使用语义名称，不复用挑战的 A/B/C 单字母 ID：

```text
wordToMeaning
audioToWord
meaningToWord
```

### 5.1 `wordToMeaning`

展示：

```text
英文单词
→ 选择正确中文意思
```

要求：

- 优先 4 个唯一中文选项；
- 正确答案必须存在；
- 中文重复时不得作为干扰项；
- 不显示完整卡片内容。

### 5.2 `audioToWord`

展示：

```text
播放英文发音
→ 选择正确英文单词
```

要求：

- 进入题目时可尝试自动播放；
- 必须有可点击的“再听一次”按钮；
- 自动播放失败不得判错；
- 选项是唯一英文词；
- 题干不得提前显示答案单词。

### 5.3 `meaningToWord`

展示：

```text
中文意思
→ 选择正确英文单词
```

要求：

- 优先 4 个唯一英文选项；
- 正确答案必须存在；
- 不得把同一标准化单词重复放入选项。

### 5.4 题型分配

题型分配必须：

- 可复现；
- 同一 session、同一 plan item 刷新后保持一致；
- 不使用 `sort(() => Math.random() - 0.5)` 决定正式题型；
- 尽量避免与该词 `lastTaskType` 相同；
- 三种题型在一批 screening 中都有机会出现。

推荐使用：

```text
session.date
+ wordKey
+ plan index
```

生成稳定 seed，再进行确定性选择。

计划项不要求在作答前额外保存 `taskType`；只要刷新后能确定性得到相同题型即可。正式结果保存时必须把 `taskType` 写入：

```text
session.plan[cursor].taskType
words[wordKey].lastTaskType
```

## 6. 选项生成规则

### 6.1 候选来源

干扰项只能来自：

```text
collectVisibleVocabularyAdventureCandidates()
```

即当前学生可见的正式 `common` 词本。

不得使用：

- support 词本；
- 当前学生不可见词；
- 虚构词；
- 硬编码无关词；
- 旧 known / unknown 词本结果。

### 6.2 唯一性与降级

优先生成 4 个选项。

若唯一候选不足：

```text
4 → 3 → 2
```

最低必须有 2 个有效选项。

若连 2 个都无法构建：

- 不得把当前词标记 D / H / F；
- 显示明确的本地错误；
- 保持 cursor 不变；
- 完成报告中列出词和原因。

### 6.3 刷新稳定

同一 plan item 的：

- 题型；
- 正确答案位置；
- 干扰项集合；
- 干扰项顺序；

在刷新后必须保持一致。

推荐实现确定性 shuffle，不保存完整题目快照。

## 7. 一次提示与 D / H / F

每个词的运行时状态至少包括：

```text
attemptCount
hintUsed
locked
preparedResult
```

### 7.1 第一次正确

```text
第一次作答正确
→ D
```

不得显示提示。

### 7.2 第一次错误

第一次错误时：

- 不写入正式结果；
- 不增加 `reviewCount`；
- 不前进 cursor；
- 禁用本次错误选项；
- 只给一次轻提示；
- 保持同一题型、同一正确答案和同一选项集合。

### 7.3 提示内容

提示按题型区分：

#### `wordToMeaning`

优先：

- 重播发音；
- 显示已有 emoji（若有）；
- 禁用已选错误项。

不得直接显示中文答案。

#### `audioToWord`

使用：

- 再播放一次发音；
- 显示英文首字母；
- 禁用已选错误项。

#### `meaningToWord`

使用：

- 显示英文首字母；
- 可重播发音；
- 禁用已选错误项。

不得在提示阶段显示完整单词。

### 7.4 提示后正确

```text
第一次错误
→ 提示
→ 第二次正确
→ H
```

### 7.5 提示后仍错误

```text
第一次错误
→ 提示
→ 第二次仍错误
→ F
```

F 后必须显示完整单词卡，包括现有字段中可用的：

- word；
- meaning；
- pos；
- phonetic；
- emoji；
- collocations；
- irregularForms；
- synonyms；
- wordFamily；
- tip；
- 发音按钮。

不得新增或修改单词卡字段。

### 7.6 禁止的交互

本轮不得提供：

- 跳过；
- 直接显示答案；
- 无限重试；
- 第三次作答；
- 手工选择 D / H / F；
- “我认识 / 我不认识”自评按钮。

## 8. 正式结果必须原子化准备

不得由播放器分别零散修改：

```text
words
session.plan
session.cursor
session.phase
session.completed
```

推荐在核心层新增纯函数，例如：

```js
prepareVocabularyAdventureResult(state, {
  expectedCursor,
  wordKey,
  taskType,
  result,
  reviewedAt
})
```

函数必须：

1. 先规范化 state；
2. 确认 session 存在且未完成；
3. 确认 `session.cursor === expectedCursor`；
4. 确认当前 plan item：
   - `phase === 'screening'`
   - `status === 'pending'`
   - `wordKey` 匹配；
5. 调用现有 `applyAdventureResult()`；
6. 将返回词状态的 `lastTaskType` 更新为当前题型；
7. 更新当前计划项：
   - `taskType`
   - `status = completed`
   - `result = D/H/F`
8. 游标前进一步；
9. 用现有 cursor 规范函数更新：
   - cursor；
   - phase；
   - completed；
10. 返回一个新的规范化 state；
11. 不直接保存、不修改输入对象。

若验证失败，应返回明确失败或抛出可测试错误，不得重复增加 `reviewCount`。

## 9. 保存成功后才能前进

### 9.1 保存流程

正式结果流程必须是：

```text
生成 prepared nextState
→ 调用 saveVocabularyAdventureState()
→ 保存成功
→ 更新播放器运行时 state
→ 显示结果反馈
→ 允许进入下一词
```

### 9.2 保存失败

保存失败时：

- 不得进入下一词；
- 不得把 UI 进度推进；
- 不得假装已经完成；
- 显示“保存失败，重新保存”；
- 保留同一个 `prepared nextState`；
- 重试保存时保存同一个状态对象；
- 不得再次调用 `applyAdventureResult()`；
- 不得让 `reviewCount` 重复增加。

该设计还必须覆盖：

```text
云端实际已收到写入
但客户端因网络中断认为失败
```

重试同一完整状态仍应是幂等写入。

### 9.3 首次创建 session 失败

`loadOrCreateVocabularyAdventureSession()` 返回：

```text
action = created
saved = false
```

时，不得进入答题页。

必须显示保存失败，并允许重新创建或重试保存。

## 10. 当前计划项的单词解析

不得只依赖：

```text
batchId + cardIndex
```

因为词本内容在 session 创建后可能被编辑或移动。

解析顺序建议：

1. 从当前可见候选词中按 `wordKey` 查找；
2. `batchId + cardIndex` 只作为快速提示和一致性校验；
3. 若索引卡片的标准化词与 `wordKey` 不一致，使用按 key 找到的卡片；
4. 若当前词已经不存在或不再可见：
   - 不得使用错误索引卡片；
   - 不得自动标记完成；
   - 停在当前项并报告；
   - 不得静默跳过。

## 11. Session 与阶段边界

### 11.1 同日恢复

若返回：

```text
action = resume_today
```

必须从保存的 cursor 恢复。

已完成计划项不得重新作答。

### 11.2 前日未完成

若返回：

```text
action = resume_previous
```

继续旧 session，不生成今天新计划。

页面应清楚显示旧 session 日期，但不得自动覆盖。

### 11.3 当日已完成

若返回：

```text
action = completed
```

显示完成页，不生成第二套计划。

### 11.4 进入 review 阶段

若当前项：

```text
phase = review
```

本轮只显示阶段边界：

```text
第一站摸底已完成
第二站抗遗忘将在后续执行卡接入
```

要求：

- 不构建 review 题；
- 不调用 `js/review.js` 的现有整轮流程；
- 不更新当前 review 计划项；
- 不把整个 session 标记完成；
- 允许返回首页。

### 11.5 首次 30 个纯 screening

首次 session 没有 review 项。

完成第 30 个词后：

```text
cursor = plan.length
completed = true
phase = completed
```

显示“今日摸底完成”。

## 14. 退出与恢复

点击退出时：

- 立即停止发音；
- 返回首页；
- 不修改当前 pending 项；
- 已保存结果保留；
- 不弹出“整轮放弃”；
- 下次进入从保存 cursor 恢复。

若当前结果已经准备但尚未保存：

- 必须提示仍有未保存结果；
- 不得静默退出并丢失；
- 可要求先重试保存或明确取消本次未保存结果；
- 取消未保存结果后，该词下次重新作答，不写 D/H/F。

## 15. 必须完成的自动测试

### 15.1 执行卡 1 前置修复

7. F 显示完整卡；

9. 最后一项完成后 session completed；
10. 重复提交同一项不会二次增加 reviewCount；

### 15.6 保存失败

1. 保存成功后才进入下一词；
2. `sbSet` 抛错时停留当前题；
3. UI 进度不前进；
4. Retry 保存同一个 prepared state；
5. Retry 不重复调用间隔算法；
6. `reviewCount` 只增加一次；
7. session 首次创建保存失败时不进入播放器。

### 15.7 恢复

1. 同日刷新恢复 cursor；
2. 同一题型和选项不变；
3. 前日未完成继续旧 session；
