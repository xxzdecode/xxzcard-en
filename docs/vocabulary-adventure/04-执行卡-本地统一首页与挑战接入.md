## 3. 统一首页的功能边界

### 3.1 预览开关

继续使用既有预览判断，不得引入第三套开关：

```text
localStorage: wc_vocab_adventure_preview = 1
```

或：

```text
?previewVocabularyAdventure=1
```

需要保证：

- 查询参数开启时生效；
- localStorage 开启时生效；
- 查询参数和 localStorage 的优先关系与执行卡 2、3 保持一致；
- 老师端不显示儿童探险首页；
- 预览关闭时 DOM、按钮和默认路由仍走旧逻辑；
- 不通过修改线上默认值来“方便测试”。

### 3.2 儿童端两个入口

预览开启后，儿童端词汇主入口只显示：

```text
探险
挑战
```

不得再让孩子在这个预览首页选择：

- 今日单词；
- 混合单词；
- 今日温习；
- 混合温习；
- 摸底；
- 抗遗忘。

旧按钮、旧函数和旧页面可以继续存在于代码中，但在预览首页不作为主入口显示。

### 3.3 探险入口状态

“探险”入口至少要正确区分：

1. 今日没有 session：
   - 点击后生成今日计划并开始；
2. 今日有未完成 session：
   - 显示“继续探险”语义；
   - 点击后从已保存 cursor 恢复；
3. 今日 session 已完成：
   - 点击后显示当天阶段总结；
   - 不重复生成第二份今日计划；
4. 存在可恢复的前一日未完成 session：
   - 继续沿用执行卡 1—3 的正式恢复规则；
   - 不在首页另写一套日期判断。

首页状态必须由核心状态计算，不得通过读取题目 DOM 猜测。

### 3.4 挑战入口状态

“挑战”入口至少要显示：

- 今日可挑战；
- 未完成挑战可继续；
- 已完成一次后的最高分和剩余次数；
- 今日次数已用完；
- 当前数据不足，暂时不能生成完整挑战。

每日次数限制必须复用旧挑战的正式规则。当前旧代码的上限为 2 次，不得在本卡中改成新数字。

退出挑战是否消耗次数，也必须保持旧挑战现有语义；若需要为恢复功能调整实现，最终用户可见规则仍应与旧挑战一致，并在交接日志中写清楚。

## 4. 挑战的正式规则

### 4.1 基本规则

挑战继续是独立入口，规则为：

```text
10 道综合题
无提示
正式计分
显示正确数
显示错误数
显示错题
保留每日次数限制
```

挑战不能调用探险中的“一次提示”流程。

答错后可以显示正确答案和完整卡信息，但不能把这种反馈当作提示后重新作答，也不能把结果记成 H。

### 4.2 挑战题型

优先复用旧挑战已经注册的可用题型及其渲染、判题能力：

- 例句填空；
- 选英文；
- 选中文；
- 听力辨词；
- 拼写；
- 字母排序；
- 听音拼写；
- 音标选词；
- 搭配补全；
- 句子排序。

不得为了“统一”而删除旧题型。

允许新增探险挑战适配层，把旧题型转成可序列化、可恢复的 challenge plan；不建议直接把旧的全局变量式整轮控制器嵌入探险核心状态。

建议新增独立模块，例如：

```text
js/vocabularyAdventureChallenge.js
```

该模块负责：

- 挑战候选词；
- 确定性题型分配；
- 10 题计划构建；
- 题目可用性检查；
- 判题结果的标准化；
- 挑战 session 的纯函数汇总；
- 错词标记准备；
- 保存失败重试所需的 prepared result。

旧 `quiz.js`、`tasks.js`、`questionTypes.js` 只做必要的兼容接线，不得破坏旧入口。

## 5. 统一挑战取词

### 5.1 候选数据来源

挑战必须从当前孩子可见的正式单词候选池中按 `wordKey` 取词，不得再依赖失效的 `batchId + cardIndex` 作为唯一定位。

候选池应复用执行卡 1—3 已经建立的：

- 可见词卡合并；
- `wordKey` 生成与解析；
- 重复词处理；
- 隐藏或失效词过滤；
- sister / brother 独立状态。

挑战不应改变单词卡原有字段。

### 5.2 参与挑战的词

挑战应优先使用已经完成基础摸底、具备正式词汇状态的词。

未摸底词不应因为旧挑战的随机逻辑而被突然加入正式挑战；这些词应先通过探险完成基础连接判断。

具体实现时：

```text
有正式 word state / 已完成 screening
→ 可进入挑战候选池

仍属于历史未摸底
→ 不进入正式挑战候选池
```

若本地实际数据结构没有单独的 `screenedAt`，使用执行卡 1—3 已存在的正式判定函数，不得新增一套含义相同但不一致的判断。

### 5.3 10 个目标词

正常情况下生成 10 个不同目标词，每词对应 1 道题。

要求：

- 同一轮优先不重复目标词；
- 候选词不少于 10 时必须得到 10 个不同目标词；
- 不允许像旧 `prioritizedTaskDeck()` 一样通过随机复制词卡强行补足；
- 少于 10 个正式候选词时，不得伪装成完整 10 题挑战；
- 显示“可挑战词不足 10 个，请先完成探险”；
- 不消耗挑战次数；
- 不创建半成品正式 challenge session。

### 5.4 取词优先级

统一取词不能继续依赖旧 `known / new / unknown` 数组作为唯一依据。

建议优先级：

```text
当前已到期或较薄弱、但不属于本轮未处理 challenge pending 的正式词
→ 其他已摸底词
→ 稳定词
```

但挑战不是抗遗忘调度器，不需要复制探险的完整 review priority。

关键要求是：

- 不只抽最新一个 batch；
- 不只抽旧 mixed batch；
- 不包含未摸底词；
- 不因挑战抽词直接改变 D/H/F；
- 使用当前孩子独立状态；
- 挑战计划一旦生成，刷新后顺序不变化。

如果本地已有正式产品文档或执行卡 1 的函数给出了更明确的 challenge 候选规则，以最新 Git 正式规则为准，并在交接日志说明实际采用规则。

### 5.5 确定性

正式挑战计划不得在构题阶段使用 `Math.random()`。

seed 至少包含：

```text
session date
user key
challenge attempt index
wordKey
question index
```

需要确定性的内容包括：

- 目标词顺序；
- 题型分配；
- 选择题选项；
- 字母顺序；
- 缺字位置；
- 句子顺序；
- 其他可恢复的题面随机项。

同一个已保存 challenge session 刷新后必须得到完全相同的题目和选项。

旧题型内部若仍使用 `Math.random()`，本卡需要：

- 给探险挑战提供确定性参数或适配构题函数；
- 不得通过临时覆盖全局 `Math.random()` 实现；
- 不要求重写所有旧入口，只要求新挑战路径确定性。

## 6. 挑战 session 数据

继续保存在当前孩子的：

```text
vocab_adventure_v1_sister
vocab_adventure_v1_brother
```

不得新增 Supabase 表。

建议在既有状态中加入单个当前挑战 session，例如：

```js
challengeSession: {
  date,
  attemptIndex,
  seed,
  status,          // active | completed
  items,
  cursor,
  correctCount,
  wrongCount,
  wrongItems,
  startedAt,
  updatedAt,
  completedAt
}
```

字段名可以按现有代码风格调整，但必须满足：

- 可恢复；
- 可判定是否完成；
- 可显示结果；
- 可防止重复计分；
- 可在保存失败时重试相同结果；
- 不保存无限历史日志。

完成后只保留本日所需的当前汇总和错题展示数据，不建立长期逐次点击日志。

挑战题 item 至少要保存或可稳定重建：

```text
wordKey
taskType
prepared question data
correct answer
user answer
result
answeredAt
```

不要只保存 DOM 下标。

## 7. 单题判定与原子保存

### 7.1 每题只判定一次

回答确认后：

1. 锁定当前题；
2. 纯函数计算本题正确或错误；
3. 生成 prepared challenge result；
4. 保存到当前孩子状态；
5. 保存成功后再更新正式计分和显示“下一题”；
6. 保存失败则保留当前题和同一个 prepared result；
7. 点击重试时不得再次判题或重复计数。

需要提供与执行卡 2、3 同等级别的接口，例如：

```text
prepareVocabularyChallengeAnswer()
applyVocabularyChallengeAnswer()
```

实际命名可调整。

### 7.2 最后一题

最后一题保存必须原子包含：

- 本题结果；
- 最终 correctCount / wrongCount；
- wrongItems；
- challenge session completed；
- 本次挑战次数；
- 本日 bestScore；
- 所有挑战错词的待复查标记。

任一部分保存失败：

- 不显示正式结果页；
- 不增加次数；
- 不重复添加错题；
- 不提前标记 session completed。

### 7.3 中途退出和刷新

刷新或重新进入：

- 从已保存 cursor 继续；
- 已回答题不再重新计分；
- 当前未确认题保持原题面；
- 当前已经保存但尚未点击下一题的状态要可恢复；
- 不因为刷新重新生成不同选项。

退出挑战的用户确认和次数消耗保持旧规则。

## 8. 挑战错词回流

### 8.1 只写挑战待复查

挑战答错时，对目标词写入既有正式字段：

```text
challengeFlagAt
```

或执行卡 1—3 实际采用的同义字段。

禁止直接：

- 设置 `F`；
- 设置 `H`；
- 改为陌生；
- 把 interval 重置为 1；
- 修改 `nextDueAt`；
- 增加探险 `reviewCount`；
- 把挑战答错当作一次正式抗遗忘结果。

挑战只说明“需要下一次探险确认”。

### 8.2 正确题的处理

挑战答对：

- 不升级 interval；
- 不推进 D；
- 不清除旧的 challenge pending；
- 不增加探险 reviewCount；
- 只计入本次挑战分数。

如果某个词之前已经是 challenge pending，本次挑战答对也不能清除它；必须等下一次探险正式检索。

### 8.3 同一词重复答错

正常 10 题计划不重复目标词，因此一轮内原则上不会重复写同一个词。

若因旧数据或恢复异常遇到重复：

- 只保留一个 pending 标记；
- 时间戳使用本轮最新有效错误时间；
- 不创建数组式重复记录；
- 不重复影响任何间隔字段。

### 8.4 与当前探险 session 的关系

挑战错词进入“下一次生成的探险计划”，不得偷偷改写已冻结计划。

规则：

1. 今日探险计划已生成但未完成：
   - 当前 plan 不插题；
   - challenge pending 留到下一次新计划；
2. 今日探险已完成后再挑战：
   - 留到下一次可生成的探险；
3. 今日尚未生成探险，先做挑战：
   - 随后首次生成的探险可以按正式 planner 规则读取 challenge pending；
4. 当前 plan 已经包含同一词：
   - 不重复插入；
5. challenge pending 被下一次探险处理后：
   - 清除 challenge 标记；
   - 再按该次探险 D/H/F 更新状态；
   - 若结果为 F，后续来源变为 failed，而不是继续挂 challenge。

不得在挑战模块复制一套新的探险候选排序。由执行卡 1 的 planner 继续负责：

```text
挑战待复查
→ F
→ H
→ 严重逾期
→ 正常到期
→ 稳定抽查
```

## 9. 旧挑战每日次数兼容

旧挑战当前使用每日最多 2 次，并保存：

```text
attempts
bestScore
checkedIn
```

本卡需要统一儿童预览挑战入口，但不得破坏旧入口的次数记录。

必须先检查实际数据键和旧逻辑，然后选择一种兼容方案：

### 推荐方案

为新挑战在 adventure state 内保存可恢复 session，同时继续复用旧正式的每日挑战次数记录，完成挑战时原子或有明确补偿地更新两处。

但两处保存容易产生部分成功，因此更优先：

- 若现有 adventure state 已经通过同一个 `kv_store` 键原子保存，可把新入口的当日 attempts / bestScore 迁入 adventure state；
- 同时提供旧入口读取兼容层；
- 不能让预览开关开关前后分别获得两套 2 次机会。

无论采用哪种方案，验收必须证明：

```text
预览挑战与旧挑战共用同一个每日次数上限
```

不得出现：

```text
旧入口 2 次 + 新入口 2 次
```

如果兼容迁移会明显扩大本卡范围，优先做适配读取与单一写入源，并在交接日志记录取舍。

## 10. 结果页

挑战完成后显示：

- 得分；
- 正确题数；
- 错误题数；
- 错题目标词；
- 每道错题的题型；
- 用户答案；
- 正确答案；
- 今日已用次数；
- 今日剩余次数；
- 今日最高分。

错题列表必须来自已保存的 challenge session summary，不得只读取当前页面 DOM。

结果页不需要地图、宝箱、金币或动画。

结果页可以提供：

- 返回词汇首页；
- 次数未用完时再次挑战；
- 查看错题完整卡。

再次挑战必须新建下一 attemptIndex 和新 seed，不复用上一轮结果，也不能覆盖上一轮尚未成功保存的结果。

### 原则

- challenge 计划和结果逻辑尽量是纯函数；
- DOM 渲染留在 player 或 challenge UI 层；
- 云端读写继续走既有保存入口；
- 不复制 `applyAdventureResult()` 的间隔算法；
- challenge 错误只写 pending，不调用 `applyAdventureResult(F)`；
- 旧 challenge 入口继续可运行；
- 不删除旧函数；
- 不大规模重命名与本卡无关的代码。

如果实际只需修改更少文件，以最小改动为优先。

## 12. 单元测试

至少覆盖以下内容。

### 12.1 首页

1. 预览关闭显示旧入口；
2. query 开启显示“探险 / 挑战”；
3. localStorage 开启显示“探险 / 挑战”；
4. 老师端不显示儿童探险首页；
5. 未完成探险显示继续；
6. 已完成探险显示总结入口；
7. 未完成挑战显示继续；
8. 次数已用完显示锁定；
9. 开关关闭后旧入口状态计算不受影响。

### 12.2 挑战候选池

1. 只使用可见词；
2. 只使用已完成基础摸底的词；
3. 两个孩子候选状态独立；
4. 不使用失效 `cardIndex` 定位；
5. 候选不少于 10 时生成 10 个不同目标词；
6. 少于 10 个时拒绝开始且不消耗次数；
7. 不通过复制词卡补足；
8. 刷新后目标词顺序一致；
9. attemptIndex 改变时可得到新的确定性计划；
10. 不修改探险 plan。

### 12.3 题型和构题

1. 10 道题可完整生成；
2. 所有题无提示分支；
3. 题型不可用时回退到其他安全挑战题型；
4. 无可用题型时安全停止且不创建正式 session；
5. 选择题至少有足够有效选项；
6. 不出现相同文本的重复选项；
7. 拼写、排序、句子顺序确定性；
8. 正式构题路径不使用 `Math.random()`；
9. 每道题可序列化和恢复；
10. 旧 challenge 题型注册未被破坏。

### 12.4 保存

1. 正确题只增加 challenge correctCount；
2. 错误题只增加 wrongCount 和 wrongItems；
3. 错误题写 challenge pending；
4. 错误题不设置 F；
5. 错误题不重置 interval；
6. 错误题不增加探险 reviewCount；
7. 正确题不清除既有 challenge pending；
8. 保存失败不更新正式 UI 计分；
9. 重试同一个 prepared result 不重复计数；
10. 最后一题保存失败不显示结果；
11. 最后一题重试后只增加一次 attempts；
12. bestScore 正确更新；
13. 中途刷新后 cursor 正确恢复；
14. sister / brother 保存完全隔离。

### 12.5 回流

1. challenge pending 在 planner 中优先于 failed；
2. 已冻结当前 plan 不被挑战结果改写；
3. 新计划可以选中 challenge pending；
4. 同一词不重复进入 plan；
5. 探险正式结果清除 challenge flag；
6. 探险结果为 F 后来源转为 failed；
7. 挑战答对不能清除 pending；
8. 重复保存不产生多个 pending 记录。

### 12.6 每日次数

1. 上限继续为 2；
2. 新旧入口共用上限；
3. 第一次完成后显示剩余 1 次；
4. 第二次完成后锁定；
5. 保存失败不消耗次数；
6. 数据不足不能开始时不消耗次数；
7. 按旧规则退出时只消耗一次；
8. 次日自动进入新一日记录；
9. bestScore 取两次中的最高值。

## 13. 浏览器与手工 QA

至少在本地 WebKit 验证：

```text
1024 × 768
1180 × 820
```

不要求本轮做视觉打磨，但必须保证：

- 无水平滚动；
- 主按钮可点击；
- 挑战 10 题可以完整走通；
- 选择、拼写和排序控件可操作；
- 固定反馈条不遮挡确认或下一题按钮；
- 结果页可滚动查看全部错题；
- 按钮点击区域不小于现有最低标准；
- 刷新后恢复；
- 浏览器返回后状态不重复提交。

手工流程至少完成：

### 流程 A：旧功能保护

```text
关闭预览
→ 打开儿童首页
→ 今日单词 / 混合单词仍按旧逻辑显示
→ 旧温习可进入
→ 旧挑战可进入
```

### 流程 B：统一首页

```text
开启预览
→ 只显示探险 / 挑战
→ 探险可开始或继续
→ 返回首页后状态正确
```

### 流程 C：完整挑战

```text
准备至少 10 个已摸底词
→ 开始挑战
→ 完成 10 题
→ 查看分数、错题和剩余次数
→ 再挑战一次
→ 第三次被锁定
```

### 流程 D：错词回流

```text
在挑战中故意答错至少 2 个词
→ 检查这些词只新增 challenge pending
→ 检查 interval / D/H/F 未被挑战修改
→ 生成下一次新探险计划
→ challenge pending 优先进入 review
→ 完成探险题
→ challenge flag 被正式清除
```

### 流程 E：保存失败

模拟：

- 普通题保存失败；
- 最后一题保存失败；
- challenge pending 保存失败；
- attempts 保存失败。

验证：

```text
不重复计分
不提前显示结果
不多消耗次数
不产生重复 pending
重试后只成功一次
```

### 流程 F：两个孩子

```text
sister 完成一轮挑战并产生错词
→ 切换 brother
→ brother 不出现 sister 的分数、次数、session 或 pending
→ brother 独立完成挑战
→ 切回 sister 状态仍正确
```
