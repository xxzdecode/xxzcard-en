## 1. 本轮唯一目标

建立一个独立、可测试的“词汇探险计划引擎”，完成：

```text
读取学生探险状态
→ 汇总可见正式常用词
→ 识别未摸底词
→ 识别到期或待复查词
→ 生成当天固定计划
→ 计算 D / H / F 后的下一次复习日期
→ 保存和恢复当天计划
```

本轮**不制作练习页面**，不让孩子真正开始答题。

验收重点是：

- 数据结构是否稳定；
- 取词是否正确；
- 第一次 30 个摸底是否正确；
- 后续 20 个摸底 + 10 个抗遗忘是否正确；
- 词池不足时补位是否正确；
- 两个孩子状态是否隔离；
- 同一天刷新后计划是否保持不变；
- 间隔计算是否正确。

## 5. 状态结构

建议使用以下结构；可以根据现有代码风格调整字段命名，但语义不得缺失。

```json
{
  "version": 1,
  "words": {
    "apple": {
      "lastResult": "D",
      "intervalIndex": 1,
      "lastReviewedAt": "2026-07-28T10:00:00.000Z",
      "nextReviewAt": "2026-07-31",
      "reviewCount": 1,
      "lastTaskType": "wordToMeaning",
      "challengeFlagAt": ""
    }
  },
  "session": {
    "date": "2026-07-28",
    "plan": [],
    "cursor": 0,
    "phase": "screening",
    "completed": false,
    "rewardGranted": false
  }
}
```

### 5.1 必须提供的默认状态

```js
{
  version: 1,
  words: {},
  session: null
}
```

允许 `session` 为 `null`，或使用等价空结构，但必须统一。

### 5.2 单词状态必要字段

| 字段 | 必须语义 |
|---|---|
| `lastResult` | `D`、`H`、`F` 或空 |
| `intervalIndex` | 当前位于间隔序列的索引 |
| `lastReviewedAt` | 最近一次正式判断时间 |
| `nextReviewAt` | 下一次到期本地日期 |
| `reviewCount` | 正式判断次数 |
| `lastTaskType` | 后续避免连续使用同一题型 |
| `challengeFlagAt` | 挑战错题待复查标记 |

### 5.3 本轮不增加

不得增加或依赖：

- 完整 attempts 数组；
- 每次点击日志；
- response time 历史；
- 每类题型累计分数；
- 长期 usage 等级；
- 全量 session 历史；
- 单词本内 known / unknown 迁移。

## 6. 单词标准化与唯一键

提供纯函数，例如：

```js
normalizeAdventureWord(value)
```

最低规则：

```text
String
→ trim
→ lower case
→ 连续空白合并为一个空格
```

空值返回空字符串。

MVP 使用标准化英文核心词作为状态 key。

生成候选词时必须：

- 去掉空词；
- 去重；
- 保留第一条可用卡片；
- 不修改原始单词卡。

### 6.1 同词异义

本轮不提前改为 `batchId::word`。

但代码应集中封装 key 生成方法，未来可迁移，不要在多个模块中直接散写：

```js
word.trim().toLowerCase()
```

## 7. 可用词池

从当前学生可见的正式词本中汇总候选。

MVP 默认只包括：

```text
bookPurpose = common
```

排除：

- `support` 辅助词本；
- 未推送给当前学生的词本；
- 缺少 `word`；
- 缺少 `meaning`；
- 重复标准化词；
- 当前用户不可见的词本。

需要保留每个候选词的来源信息，至少：

```json
{
  "key": "apple",
  "word": "apple",
  "batchId": "book-id",
  "batchName": "常用词1",
  "cardIndex": 0,
  "card": {}
}
```

若当前正式代码对可见词本和 `bookPurpose` 已有函数，必须复用，不得复制一套不一致的过滤规则。

## 8. 词池分类

### 8.1 未摸底词

定义：

```text
状态表中不存在该词
或 reviewCount = 0
```

未摸底词不依赖现有 `known / unknown`。

当前正式规则已经明确不继续维护 `known / unknown` 作为新系统依据，因此不得将它们作为探险状态真相。

### 8.2 挑战待复查词

定义：

```text
challengeFlagAt 非空
```

本轮只实现分类逻辑和测试，不需要修改挑战流程写入该字段。

### 8.3 失败词

```text
lastResult = F
```

### 8.4 提示词

```text
lastResult = H
```

### 8.5 严重逾期词

建议定义：

```text
nextReviewAt < today
且逾期至少 2 天
```

如果执行卡实现采用更明确的天数函数，必须写入测试。

### 8.6 正常到期词

```text
nextReviewAt <= today
```

且不属于更高优先级分类。

### 8.7 稳定抽查词

建议：

```text
lastResult = D
intervalIndex 对应 30 或 60 天
nextReviewAt > today
```

MVP 只有在未摸底和到期词不足时才允许少量用于补位。

---

## 9. 抗遗忘优先级

排序固定为：

```text
1. challengeFlagAt 非空
2. lastResult = F
3. lastResult = H
4. 严重逾期
5. 正常到期
6. 稳定抽查
```

同一优先级内：

```text
nextReviewAt 更早
→ lastReviewedAt 更早
→ 原词本顺序更早
```

必须保证排序可复现。

不得使用：

```js
sort(() => Math.random() - 0.5)
```

来决定正式计划。

## 10. 当天计划生成

提供纯函数，例如：

```js
buildVocabularyAdventurePlan({
  candidates,
  state,
  today,
  screeningTarget = 20,
  reviewTarget = 10,
  firstSessionTarget = 30
})
```

函数名可调整，但必须可单元测试。

### 10.1 首次使用

判定：

```text
words 中没有任何 reviewCount > 0 的词
```

生成：

```text
最多 30 个未摸底词
0 个抗遗忘词
```

若可用未摸底词少于 30：

```text
处理全部，不重复凑数
```

### 10.2 后续正常阶段

默认目标：

```text
20 个未摸底词
10 个抗遗忘词
```

固定阶段顺序：

```text
所有 screening 项
→ 所有 review 项
```

计划项至少包括：

```json
{
  "wordKey": "apple",
  "word": "apple",
  "batchId": "book-id",
  "cardIndex": 0,
  "phase": "screening",
  "taskType": "",
  "status": "pending",
  "result": ""
}
```

本轮 `taskType` 可以暂时为空，后续播放器填充。

### 10.3 抗遗忘不足时

先取全部可用抗遗忘词，再用更多未摸底词补至最多 30：

```text
例如：
抗遗忘 4
未摸底充足
→ 26 摸底 + 4 抗遗忘
```

### 10.4 未摸底不足时

先取全部未摸底词，再用更多抗遗忘词补至最多 30：

```text
例如：
未摸底 7
抗遗忘充足
→ 7 摸底 + 23 抗遗忘
```

### 10.5 总池不足

```text
未摸底 + 抗遗忘 < 30
→ 只处理全部可用唯一词
```

不得：

- 重复词；
- 使用不可见词；
- 使用辅助词；
- 虚构词；
- 为凑数重复稳定词。

### 10.6 同词冲突

同一词同时属于多个抗遗忘分类时，只出现一次，并使用最高优先级。

同一词不能同时进入 screening 和 review。

---

## 11. 未摸底词排序

本轮不随机。

建议顺序：

```text
较早的正式常用词本
→ 词本内 card 原始顺序
```

“较早”应根据当前正式词本排序字段或现有排序函数定义。

若仓库没有可靠创建时间，只能使用当前稳定可复现顺序，不得猜测日期。

必须在完成报告中说明实际采用的顺序来源。

## 12. 当日 session 规则

### 12.1 同一天只生成一次

若状态中存在：

```text
session.date = today
session.completed = false
```

则返回原计划，不重新生成、不重排、不补入新词。

### 12.2 已完成

若：

```text
session.date = today
session.completed = true
```

返回已完成状态，不生成第二套计划。

### 12.3 新日期

若旧 session 已完成：

```text
生成今天的新计划
```

若旧 session 未完成：

```text
MVP 默认继续旧计划
```

本轮只需在核心层返回明确状态，例如：

```js
{
  action: 'resume_previous',
  session
}
```

不得自动覆盖旧计划。

### 12.4 游标

提供更新 session 游标的纯函数或安全方法。

最低约束：

- 游标不能小于 0；
- 不能大于计划长度；
- 完成时 cursor = plan.length；
- completed 与 cursor 保持一致。

本轮不需要页面调用，但必须测试。

## 13. 复习间隔

固定序列：

```js
[1, 3, 7, 14, 30, 60]
```

提供纯函数，例如：

```js
applyAdventureResult(previousWordState, result, reviewedAt)
```

### 13.1 首次摸底

若之前 `reviewCount = 0`：

#### D

```text
intervalIndex = 1
nextReviewAt = 3 天后
```

#### H

```text
intervalIndex = 0
nextReviewAt = 1 天后
```

#### F

```text
intervalIndex = 0
nextReviewAt = 1 天后
```

### 13.2 后续抗遗忘

#### D

```text
intervalIndex + 1
最高停在 60 天级
```

#### H

```text
保持当前 intervalIndex
```

若旧数据没有合法 intervalIndex，按 1 天级处理。

#### F

```text
intervalIndex = 0
```

### 13.3 所有正式结果更新

必须更新：

- `lastResult`；
- `intervalIndex`；
- `lastReviewedAt`；
- `nextReviewAt`；
- `reviewCount + 1`。

处理 D / H / F 后，清除：

```text
challengeFlagAt
```

因为该词已经完成探险中的正式复查。

### 13.4 日期

`nextReviewAt` 使用本地日期：

```text
YYYY-MM-DD
```

不能使用 UTC 日期截断导致日本或中国时区跨日错误。

测试应使用注入的日期函数或固定时区无关逻辑，不依赖测试运行机器的当前时间。

## 17. 必须完成的自动测试

至少覆盖以下测试。

### 17.1 标准化

1. 大小写合并；
2. 首尾空格；
3. 连续空格；
4. 空词排除；
5. 重复词保留第一条。

### 17.2 可见词池

1. 只取当前学生可见词本；
2. 排除 `support`；
3. 排除缺 `word`；
4. 排除缺 `meaning`；
5. 保留来源 `batchId / cardIndex`。

### 17.3 首次计划

1. 30 个未摸底词；
2. 无抗遗忘；
3. 少于 30 时全部返回；
4. 不重复；
5. 阶段全部为 `screening`。

### 17.4 后续 20 + 10

1. 正常生成 20 screening + 10 review；
2. screening 在前、review 在后；
3. 抗遗忘按优先级；
4. 同词只出现一次。

### 17.5 补位

1. review 只有 4 → 26 + 4；
2. screening 只有 7 → 7 + 23；
3. 总共不足 30 → 全部且不重复；
4. 稳定抽查只在不足时使用。

### 17.6 优先级

明确验证：

```text
challenge flag
> F
> H
> severe overdue
> due
> stable
```

### 17.7 当日固定

1. 同日未完成返回同一计划；
2. 同日不因词库变化重新生成；
3. 同日已完成不生成第二套；
4. 昨日未完成返回 `resume_previous`；
5. 昨日已完成可以生成今天计划。

### 17.8 间隔

首次：

- D → 3 天；
- H → 1 天；
- F → 1 天。

后续：

- D：1→3→7→14→30→60；
- H：保持；
- F：回到 1；
- 60 天 D 不越界；
- 非法 interval 安全归一；
- 完成复查清除 challenge flag。

### 17.9 学生隔离

1. sister key；
2. brother key；
3. teacher 不写；
4. 两人的 words 和 session 不互相污染。

### 17.10 存储异常
