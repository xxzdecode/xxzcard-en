# 执行卡 6｜学生端首页信息架构与视觉重构

## 0. 执行定位

本卡只重构学生端首页的信息架构、视觉层级、入口排布和状态展示。

本卡不实现完整金币结算，不开发商城、兑换、等级、连续奖励或合作奖励；不修改老师端首页和底部三个既有学生功能。

建议分支：

```text
codex/student-home-dashboard-card-6
```

执行前先同步 `xxzdecode/xxzcard-en` 默认分支并记录实际起始 SHA。不要假定本卡编写时的 HEAD 仍是最新版本。

视觉参考：本次已确认的《童趣英语学习冒险乐园》首页概念图。

---

## 1. 已确认的产品结论

### 1.1 首页内容顺序

学生首页主体固定为：

```text
今日复习
↓
挑战测验
↓
今日新课
↓
底部原有功能
```

### 1.2 今日复习

只放一张主视觉大卡：

```text
词汇探险
完成今日路线
完成即得 10 金币
```

词汇探险的奖励只看是否完整完成，不看正确率或提示使用情况。

### 1.3 挑战测验

两张并排卡：

```text
单词挑战
10 题综合测验
最高 10 金币
```

```text
语法挑战
复习上一节课语法
```

“语法挑战”和“单词挑战”属于同一分类，因为两者都是已学内容的复习测验。

### 1.4 今日新课

两张并排卡：

```text
随堂练习
20 题 · 两次机会
最高 10 金币
```

```text
新词导览
今天的新单词
```

随堂练习和新词导览属于今天的新课内容。

### 1.5 删除与保留

从学生首页移除：

```text
今日单词
混合单词
```

这两个入口不再搬到其他区域。不要因此删除旧数据、旧函数或历史兼容逻辑；只取消学生首页入口及其首页刷新依赖。

底部区域保持现状，不改功能、不改顺序：

```text
单词卡
音标训练
专项小游戏
```

老师端首页保持现状。

## 2. 本卡实施目标

1. 将学生首页从“多个长条功能入口”改成分区图片卡片式首页。
2. 建立清晰的“复习—挑战—新课”层级。
3. 让词汇探险成为首页最大的主视觉卡。
4. 将单词挑战和语法挑战放入同一个双卡区域。
5. 将随堂练习和新词导览放入同一个双卡区域。
6. 保留底部三个既有功能，不改变其行为。
7. 为累计金币和今日金币预留只读展示接口，但本卡不实现正式结算写入。
8. 妥善处理随堂练习尚未开放给学生的现状，不绕过老师权限。

```html
<section id="studentDashboard" class="student-dashboard student-only">
  <header class="student-summary-card">

  </header>

  <section class="student-home-section student-home-section--challenge">
    <h2>挑战测验</h2>
    <div class="student-home-card-grid">

  <section class="student-home-section student-home-section--lesson">

  <!-- 保持既有三个入口 -->
```

不要继续使用一张张独立长条按钮堆叠成首页。

## 4. 顶部学生信息区

### 4.1 展示内容

顶部紧凑展示：

```text
当前孩子：姐姐 / 弟弟
累计金币：N
今日金币：N / 30
今日金币进度条
```

不要增加：

```text
等级
称号
经验条
能量
签到
排行榜
商城入口
连续奖励
合作奖励
```

### 4.2 数据边界

本卡只建立只读渲染接口，例如：

```js
renderStudentRewardSummary({
  totalCoins,
  todayCoins,
  todayMaxCoins: 30,
  available
});
```

如果正式金币数据源尚未接入：

- 不写入假数据；
- 不用硬编码的 126.5 或 18/30 冒充真实结果；
- 可以显示“金币统计准备中”，或在 `available === false` 时隐藏数值区；
- 不得在本卡中自行设计新的数据库表或奖励结算逻辑。

正式金币计算放到下一张执行卡。

## 5. 卡片设计规范

### 5.1 总体风格

沿用已确认概念图的感觉：

- 柔和蓝天、浅绿、奶油白等儿童友好配色；
- 圆角卡片和轻阴影；
- 图片或插画占主要视觉，不做纯文字按钮；
- 文字层级清楚，避免在图片上堆大量说明；
- 页面背景可以带轻量地图或自然场景感，但不能影响阅读；
- 触控区域不小于 44px；
- 支持 `prefers-reduced-motion`。

### 5.2 视觉层级

#### 词汇探险

- 占满整行；
- 高度明显大于其他卡片；
- 以地图、路径、节点、探险向导为核心视觉；
- 显示“完成今日路线”和“10 金币”；
- 可显示简化路线“摸底 → 抗遗忘”；
- 不在首页卡片中增加自由地图、等级、宝箱商城等玩法。

#### 单词挑战 / 语法挑战

- 两张同尺寸并排；
- 使用相同版式，体现属于同一组；
- 单词挑战使用旗帜、山峰、终点等视觉；
- 语法挑战使用书本、句子积木、铅笔等视觉；
- 单词挑战显示“最高 10 金币”；
- 语法挑战不显示未确认的金币奖励。

#### 随堂练习 / 新词导览

- 两张同尺寸并排；
- 随堂练习使用教室、黑板、课本、铅笔等视觉；
- 新词导览使用单词卡、放大镜、路牌等视觉；
- 随堂练习显示“20 题 · 两次机会”和“最高 10 金币”；
- 新词导览显示“今天的新单词”。

### 5.3 插画资产规则

概念图只作为设计参考，不允许把整张截图裁块后直接当正式卡片背景。

正式实现应采用以下任一方式：

1. 项目内独立的轻量 WebP/PNG 插画资源；
2. 自制 SVG 与 CSS 场景组合；
3. 现有项目可复用的图形资源。

禁止：

- 外链第三方图片；
- 未授权素材；
- 把带文字的概念图局部裁切后重复叠加文字；
- 为追求视觉而引入大型 UI 框架。

建议资源目录：

```text
assets/student-home/
  adventure.webp
  word-challenge.webp
  grammar-challenge.webp
  classroom-practice.webp
  vocabulary-tour.webp
```

资源需压缩并控制移动端加载体积。没有正式插画时，先用 CSS/SVG 占位完成结构和响应式，不得用不相关图片临时上线。

## 6. 入口与函数映射

### 6.1 词汇探险

保留现有函数：

```js
openVocabularyAdventure()
```

新版首页不再依赖旧“今日单词 / 混合单词”快捷区。

### 6.2 单词挑战

保留现有函数：

```js
openVocabularyAdventureChallenge()
```

卡片显示名称改为“单词挑战”，不要只写“挑战”。

### 6.3 语法挑战

保留现有函数：

```js
openGrammarChallengeList()
```

仅调整首页位置和视觉，不修改语法挑战题库和判题逻辑。

### 6.4 新词导览

保留现有函数：

```js
openVocabularyReviewList()
```

仅调整首页位置和视觉，不修改导览内容。

### 6.5 随堂练习

当前随堂练习是老师端功能，本卡不能直接调用老师入口，也不能删除 `isTeacher()` 权限检查。

新增学生入口适配函数，例如：

```js
openStudentClassroomPractice()
```

本卡阶段行为：

- 如果已有当天学生随堂练习分配，进入对应学生练习；
- 如果尚无学生分配机制，显示明确的非阻塞提示：“今天的随堂练习还没有发布”；
- 不打开老师的完整随堂练习列表；
- 不在本卡中实现 20 题计分和金币写入。

学生随堂练习、两次机会与自动评分在下一张执行卡实现。

## 7. 旧入口清理策略

### 7.1 首页 DOM

移除或永久隐藏以下学生首页入口：

```text
#homeQuickActions
#todayWordBtn
#mixedWordBtn
```

### 7.2 JavaScript

`loadHome()` 不应继续为已移除的首页按钮执行无意义的数据加载。

处理方式：

- 删除学生首页对 `updateHomeTaskButtons()` 的调用；或
- 将其迁移到仍需要旧入口的页面；
- 保留旧函数和历史页面所需逻辑，避免破坏兼容功能。

不要因为首页移除入口而删除：

- 旧 `daily_task_*` 数据；
- 旧 today/mixed challenge 兼容计次；
- 单词本详情里的旧练习和挑战；
- 已有测试夹具与历史记录。

### 7.3 预览开关

新版学生首页应成为学生端正式默认布局，不再依赖“词汇探险预览开启后才替换首页快捷区”的旧逻辑。

但不要在本卡中删除所有预览兼容代码。先确保：

- 新首页默认展示；
- 旧入口不再展示；
- 探险/挑战核心功能仍可正常打开；
- 旧预览参数不会造成重复入口或空白首页。

确认回归通过后，再在后续清理卡中删除失去用途的预览分支。

每张卡允许显示简短状态，但不能让状态文字压过插画和标题。

建议状态：

### 词汇探险

```text

继续探险
今日已完成
```

### 单词挑战


### 语法挑战

```text
复习上一节课语法
```

如现有代码已有完成状态，可复用；没有则不新增复杂状态。

### 随堂练习

```text
未发布
可以开始
今日已完成
```

本卡只负责展示接口，不负责正式结算。

### 新词导览

```text
今天的新单词
```

不要新增无依据的完成奖励。

## 9. 响应式与可访问性

### 9.1 手机

- 以当前主要手机宽度为优先；
- 双卡区域始终保持两列；
- 极窄屏可减小间距、字号和插画比例，但不要自动改成上下堆叠；
- 卡片标题不能被截断；
- 页面允许纵向滚动；
- 底部原有三个功能保持可点击。

### 9.2 平板

- 内容最大宽度建议 720–880px；
- 不要把卡片无限拉宽；
- 适当增加卡片间距和插画留白。

### 9.3 可访问性

- 每张入口卡使用真实 `<button>`；
- 提供明确的 `aria-label`；
- 键盘焦点可见；
- 禁用卡片必须有 `disabled` 或 `aria-disabled`，并说明原因；
- 图片为装饰时使用空 `alt` 或 `aria-hidden`；
- 不只依赖颜色表示完成、锁定或不可用。

7. 词汇探险、单词挑战、语法挑战、新词导览入口可正确打开。
8. 随堂练习未发布时给出明确提示，不进入老师页面。

1. 老师首页布局和三个老师入口保持原样。
2. 不显示学生首页卡片。
3. 老师随堂练习入口仍正常。

### 11.3 回归

必须运行现有完整测试，并重点回归：

- 词汇探险生成、恢复、退出和保存；
- 单词挑战每日次数共享逻辑；
- 语法挑战列表和练习；
- 新词导览；
- 单词卡、音标训练、专项小游戏；
- WebKit/iPhone/iPad 视口；
- 预览参数与旧 localStorage 开关不会造成重复模块。

### 11.4 视觉验收

至少提供：

```text
姐姐首页手机截图

学生首页 iPad 截图
```

视觉验收重点：

- 不是长条入口堆叠；
- 三个分区一眼可辨；
- 复习区最突出；
- 两组双卡尺寸一致；
- 底部功能视觉弱于主任务；
- 文字在常见手机宽度下清晰完整；
- 没有为了还原概念图而新增计划外功能。
