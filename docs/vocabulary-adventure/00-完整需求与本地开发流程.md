# 儿童端词汇探险系统：完整需求总表与本地开发流程 V2

> 用途：作为后续 ChatGPT、用户与 Codex 的共同权威输入。  
> 当前原则：先完成最小 MVP；旧功能继续可用；所有开发先在本地完成和验收，未经用户明确批准不得推送、建 PR、合并或发布。

---

## 一、完整产品方向

儿童端首页的词汇主入口最终简化为两个模块：

```text
探险
挑战
```

不再让孩子选择：

- 今日单词；
- 混合单词；
- 今日温习；
- 混合温习；
- 摸底；
- 抗遗忘。

后台仍可保留旧的 `today / mixed / batch / review / challenge` 代码和取词能力，但儿童端只面对两个入口。

---

## 二、探险的完整长期逻辑

探险是系统自动编排的学习流程，不是让孩子自己选模式。

完整流程：

```text
生成今日计划
→ 探索位
→ 抗遗忘位
→ 当日弱词短固化
→ 宝藏结算
```

### 1. 探索位

探索位在不同阶段承担不同内容。

#### 系统初期

```text
历史未摸底词
```

#### 开始正常讲新词后

```text
前一天课堂讲过的新词回检
→ 数量不足时用历史未摸底词补位
```

#### 历史摸底全部结束后

```text
前一天新词回检
→ 额外薄弱词或待复查词补位
```

因此，“前日新词”和“历史摸底”不会长期叠加占用两套容量，而是共用同一组探索位置。

### 2. 抗遗忘位

抗遗忘来源：

```text
挑战待复查
→ 上次失败 F
→ 提示后正确 H
→ 严重逾期
→ 正常到期
→ 稳定抽查
```

抗遗忘不只做图片识义，还逐步覆盖：

- 图片与意义；
- 声音；
- 英文拼写；
- 音标；
- 单词补空；
- 字母排序；
- 听音拼写；
- 固定搭配；
- 简单例句；
- 简短句子排序。

### 3. 当日弱词短固化

探索过程中出现的 F，以及部分 H，可以在后半段换一种题型再次出现。

这属于同一个词的强化，不增加新的目标词数量。

---

## 三、默认数量与后续动态比例

### MVP 初始比例

首次使用：

```text
30 个历史摸底词
```

后续默认：

```text
20 个历史摸底词
+ 10 个抗遗忘目标词
```

### 正常教学后的长期替代

前一天讲了多少词，第二天优先占用探索位。

示例：

```text
前一天 8 个词
→ 8 个前日回检 + 12 个历史摸底 + 抗遗忘

前一天 20 个词
→ 20 个前日回检 + 0 个历史摸底 + 抗遗忘
```

### 后续动态比例

根据真实完成情况，可在以下比例间调整：

```text
20 探索 + 10 抗遗忘
15 探索 + 15 抗遗忘
10 探索 + 20 抗遗忘
```

判断依据：

- 到期词积压；
- 前日词无提示正确比例；
- 提示后正确数量；
- 失败数量；
- 总完成时长；
- 后半段是否乱点或疲劳。

10 个抗遗忘是 MVP 的初始数量，不是永久上限。

---

## 四、摸底与回检判定

基础检索只判断：

```text
声音 / 英文形式 / 基本意思之间的连接
```

第一次正确：

```text
D = direct
```

第一次错误后给一次轻提示。

提示后正确：

```text
H = hinted
```

提示后仍错误：

```text
F = failed
```

### 轻提示

可使用：

- 重播发音；
- 显示首字母；
- 减少一个干扰项；
- 显示已有 Emoji 或视觉；
- 重新排列选项。

### F 的处理

- 显示完整单词卡；
- 播放发音；
- 显示释义；
- 显示已有搭配或 tip；
- 安排最短间隔；
- 进入当日弱词短固化。

---

## 五、抗遗忘题型

优先复用现有温习与挑战题型。

### 基础意义

- 看词选义；
- 听音选词；
- 看视觉选词；
- 视觉—英文翻翻乐；
- 图片—声音配对。

### 单词形式

- 音标选词；
- 单词补空；
- 字母排序；
- 少量听音拼写。

### 使用拓展

- 搭配补全；
- 例句填空；
- 简短句子排序；
- 语境选词。

### 翻翻乐长期调整

当前英文—中文翻翻乐，后续优先改为：

```text
视觉卡 ↔ 英文单词卡
```

视觉降级：

```text
场景图
→ 概念图 / 组合图
→ Emoji
→ 英文—中文
```

翻翻乐主要用于强化，不单独作为延长复习间隔的强证据。

### 使用型题目误判保护

搭配、例句、句子排序答错时：

```text
使用题答错
→ 再做一题基础意义确认
```

基础意义也错误：

```text
F
```

基础意义正确：

```text
只标记本次 usage weak
→ 不把单词降为陌生
→ 间隔不升级
```

MVP 不长期保存独立“使用能力等级”。

---

## 六、复习间隔

基础间隔：

```text
1 → 3 → 7 → 14 → 30 → 60 天
```

首次摸底：

- D：3 天后；
- H：1 天后；
- F：1 天后。

后续抗遗忘：

- D：间隔前进一步；
- H：保持当前间隔；
- F：回到 1 天。

稳定词突然错误时正常降级。

---

## 七、挑战完整逻辑

挑战保留为独立入口。

特点：

- 10 道综合题；
- 不提供提示；
- 正式计分；
- 展示正确数、错误数和错题；
- 保留每日次数限制；
- 后续可继续连接金币或成绩机制。

挑战题型继续复用：

- 例句填空；
- 选英文；
- 选中文；
- 听力辨词；
- 拼写；
- 字母排序；
- 听音拼写；
- 音标选词；
- 搭配补全；
- 句子排序。

挑战错题：

```text
标记为下次探险待复查
```

但不直接：

- 设置 F；
- 重置间隔；
- 判定为陌生。

只有下一次探险的基础检索结果才能改变 D / H / F。

## 八、数据结构原则

### 1. 不重塑单词本

单词卡继续使用原有 11 字段。

学生的记忆状态不写入单词卡。

### 2. 两个孩子状态独立

每个孩子独立保存：

- D / H / F；
- 当前间隔；
- 上次复习；
- 下次到期；
- 挑战待复查；
- 当日计划和游标。

### 3. MVP 不新增 Supabase 表

继续使用现有：

```text
kv_store
```

建议 key：

```text
vocab_adventure_v1_sister
vocab_adventure_v1_brother
```

### 4. MVP 不保存完整点击历史

只保存当前汇总状态和未完成会话。

未来确实需要精细统计时，再新增日志层。

## 九、视觉完整方向

### MVP

只参考《随堂练习》成熟结构：

- 顶部紧凑栏；
- 一屏一种题型；
- 中间核心练习台；
- 底部固定反馈条；
- 简单阶段过渡；
- iPad 横屏优先。

### 后续正式视觉

固定画风：

```text
柔和童话森林
+ 木质站牌
+ 小火车
+ 固定探险路线
```

三个阶段可表现为：

```text
第一站
→ 第二站
→ 宝藏站
```

每天使用同一张固定地图，只改变：

- 火车位置；
- 站点点亮；
- 当前进度；
- 当天题目；
- 获得金币。

### 后续动画边界

只保留轻动画：

- 点击反馈；
- 正确轻弹；
- 错误轻晃；
- 提示淡入；
- 火车到站；
- 站点点亮；
- 宝箱打开；
- 金币数字变化。

不做：

- 3D；
- 路线选择；
- 大量粒子；
- 角色系统；
- 商城；
- 复杂地图；
- 游戏引擎。

## 十、金币与宝藏站

长期版本中：

```text
完成探险
→ 到达宝藏站
→ 调用已有金币机制
```

金币主要奖励：

```text
完成任务
```

不直接按正确率发放。

不使用：

- 错误扣金币；
- 必须全对才能领奖；
- 正确率越高金币越多。

防止孩子为了金币隐藏不会或反复试探。

MVP 暂时不新增金币规则，只保留现有打卡或完成记录。

## 十三、本地开发与上线保护

### 强制原则

在用户明确批准之前，Codex 不得：

- push；
- 创建 PR；
- 更新远程分支；
- 合并；
- 部署；
- 修改正式线上入口；
- 更新正式 Service Worker 缓存版本到远程。

### 允许的本地操作

Codex 可以：

- 创建本地分支；
- 修改本地文件；
- 运行本地测试；
- 启动本地服务器；
- 生成本地 QA 截图；
- 创建本地提交，方便回滚。

“本地提交”不会上传远程。

如果用户连本地提交也不希望产生，需要在执行卡中额外写明：

```text
不要 commit
```

默认推荐允许本地 commit，但绝不 push。

### 旧功能保护

新功能完成之前：

- 当前“今日单词 / 混合单词”继续保留；
- 线上页面继续使用旧入口；
- 不提前切换首页；
- 不删除旧函数；
- 不删除旧页面；
- 不修改线上默认行为。

### 新功能本地访问

建议使用本地功能开关，例如：

```text
localStorage: wc_vocab_adventure_preview = 1
```

或本地查询参数：

```text
?previewVocabularyAdventure=1
```

开关未启用时：

```text
显示旧功能
```

开关启用时：

```text
本地显示探险 / 挑战
```

最终切换上线前，再删除或更改默认开关。

## 十四、实际协作流程

### 第 1 步：ChatGPT 准备执行卡

ChatGPT 在当前产品讨论对话中负责：

- 确认需求；
- 维护本总表；
- 为每一阶段写完整 Codex 执行卡；
- 明确允许修改文件；
- 明确禁止操作；
- 写测试和验收要求。

### 第 2 步：用户打开 Codex 专用对话

建议新开一个 Codex 对话，专门处理这个功能。

首条消息提供：

1. 本总表；
2. 当前执行卡；
3. 强制“只在本地、不 push、不 PR、不发布”；
4. 目标仓库本地路径；
5. 当前旧功能必须继续可用。

### 第 3 步：Codex 完成一张执行卡

Codex：

- 只做当前执行卡；
- 在本地分支修改；
- 跑测试；
- 启动本地预览；
- 给出修改文件和本地验证说明；
- 到此停止。

不得自动进入下一张执行卡。

### 第 4 步：用户本地测试

用户在本地检查：

- 功能；
- 操作；
- 页面；
- 数据；
- 是否影响旧功能。

### 第 5 步：回到 ChatGPT 审核

用户把以下内容发回当前对话：

- Codex 完成报告；
- 本地截图；
- 发现的问题；
- 测试结果；
- 必要时提供 diff 或提交 SHA。

ChatGPT判断：

- 是否通过；
- 是否返工；
- 是否可以进入下一张执行卡。

### 第 6 步：全部本地验收后再上线

只有用户明确说：

```text
可以提交 / 可以上线
```

才单独创建“最终发布执行卡”。

发布执行卡才允许：

- push；
- PR；
- 合并；
- Service Worker 正式更新；
- 发布；
- 线上回查。

## 十五、执行卡顺序

### 执行卡 1：本地状态与计划引擎

- 独立探险状态；
- 未摸底池；
- 到期池；
- 第一次 30；
- 后续 20 + 10；
- D / H / F 间隔算法；
- 每日计划固定与恢复；
- 单元测试；
- 不改首页。

### 执行卡 2：本地摸底播放器

- 三种基础题；
- 一次提示；
- D / H / F；
- 完整卡反馈；
- 每词保存；
- 本地预览入口；
- 旧入口默认不变。

### 执行卡 3：本地抗遗忘接入

- 现有题型复用；
- 翻翻乐视觉—英文；
- 题型按状态分配；
- 使用题二次确认；
- 间隔更新；
- 阶段总结。

### 执行卡 4：本地统一首页与挑战

- 仅在预览开关启用时显示“探险 / 挑战”；
- 统一挑战取词；
- 挑战待复查；
- 旧功能未开开关时保持原样。

### 执行卡 5：本地完整 QA

- 两个孩子；
- 换设备；
- 中途恢复；
- 离线只读；
- 重复完成；
- 现有功能回归；
- iPad 横屏；
- 本地验收包。

### 最终发布执行卡

只有用户批准后创建。
