## 4. 本卡允许修什么，不允许修什么

### 4.1 必须修复

执行卡 5 中发现下列问题时，允许并要求修复：

#### P0：数据或核心流程灾难性问题

- sister / brother 数据串线；
- 覆盖或丢失已有词汇状态；
- 保存失败后重复计数或错误推进；
- 挑战答错直接错误修改 D/H/F 或 interval；
- 同一天重复生成计划并覆盖旧 session；
- 完成状态无法恢复；
- 旧功能在预览关闭时不可用；
- 老师端被儿童预览入口影响；
- 线上数据被本地测试意外改写；
- 用户无法退出或页面完全不可操作。

#### P1：阻止日常使用的问题

- 探险无法开始、继续或完成；
- 挑战无法完成 10 题；
- 结果页数据错误；
- 每日次数错误；
- challenge pending 无法进入下一次探险；
- challenge pending 无法被正式探险结果清除；
- 刷新后换题、丢 cursor 或重复提交；
- 离线状态仍允许写入并造成伪成功；
- 主要 iPad 横屏尺寸出现按钮被遮挡；
- 保存失败没有重试路径；
- 不足 10 个挑战词却创建半成品正式挑战；
- 前一日未完成 session 被错误丢弃。

### 4.2 可以修复

在不扩大范围的前提下，可以修复：

- 测试缺失；
- 明显空状态文案错误；
- 按钮 disabled 状态错误；
- 结果页轻微数据显示错误；
- 触控区域小于现有标准；
- 无障碍 label 缺失导致题目不可操作；
- 局部溢出、遮挡和滚动问题；
- 与新模块直接相关的重复函数或明显死代码。

### 4.3 不在本卡修复

以下内容只记录，不进入执行卡 5 修改：

- 正式森林视觉；
- 地图、小火车、宝箱；
- 新金币规则；
- 复杂动画；
- 前日新词回检；
- 新词替代历史摸底；
- 动态比例；

## 7. 探险完整功能验收

### 7.1 首次使用：30 个历史摸底

准备一个没有正式词状态、可见词不少于 30 的测试用户。

验证：

```text
生成 30 个历史摸底目标
→ 不混入 review
→ 计划固定
→ 刷新不换词
→ 每词首次正确为 D
→ 首次错误后只有一次提示
→ 提示后正确为 H
→ 提示后仍错误为 F
→ 每词保存成功后才前进
→ 完成后显示总结
```

检查：

- 30 个目标不重复；
- 候选不足时安全降级，不伪造重复目标；
- D 首次间隔为 3 天；
- H / F 首次间隔为 1 天；
- reviewCount 只增加一次；
- 最后一题保存失败时不提前完成；
- 重新进入已完成 session 不生成第二份计划。

### 7.2 后续使用：20 + 10

准备：

- 已完成一轮摸底；
- 至少 20 个未摸底词；
- 至少 10 个抗遗忘候选。

验证默认计划：

```text
20 screening
+ 10 review
```

并检查执行顺序固定为：

```text
先 screening
→ 后 review
```

检查补位顺序：

```text
最多 20 screening
→ 最多 10 urgent review
→ 额外 screening
→ 额外 urgent review
→ stable review 最后补位
```

稳定词不得挤占更紧急的词。

### 7.3 review 候选优先级

构造并验证：

```text
challenge pending
→ failed
→ hinted
→ severe overdue
→ due
→ stable
```

要求：

- 优先级符合正式 planner；
- 同一词只出现一次；
- 当前冻结 plan 不因后续状态变化而被重排；
- challenge pending 被选入后保留正式 reason；
- review plan item 保留 taskType、result、outcomeDetail 等必要字段。

### 7.4 抗遗忘题型

覆盖实际支持的全部安全题型：

- visualMatch；
- wordToMeaning；
- meaningToWord；
- audioToWord；
- phoneticToWord；
- missingLetters；
- letterOrder；
- audioSpelling；
- collocationCloze；
- exampleCloze；
- sentenceOrder。

验证：

- 状态与 reason 分题正确；
- 同一 session 刷新后题型、选项、顺序不变；
- 不使用不满足字段要求的题型；
- 回退顺序正确；
- 最低有效选项不足时安全停止；
- 安全停止不保存、不前进、不标记完成；
- 正式构题路径不依赖 `Math.random()`。

### 7.5 使用题二次确认

分别覆盖：

```text
使用题正确
→ D

使用题错误
→ 基础意义确认正确
→ H + usageWeak
→ interval 不升级

使用题错误
→ 基础意义确认错误
→ F
→ interval 回到 1 天
```

检查：

- 使用题错误本身不立即保存 F；
- `confirmationTaskType` 正确；
- plan item 保留原 usage taskType；
- 不新增长期 usage 能力等级；
- 保存失败重试不重复运行间隔算法。

### 7.6 视觉—英文翻翻乐

验证：

- 目标词和最多 3 个干扰词；
- 只更新目标词；
- 干扰词不增加 reviewCount；
- 无错完成为 D；
- 一次错配为 H；
- 多次错配进入基础意义确认；
- 确认正确为 H；
- 确认错误为 F；
- 键盘和触控均可操作；
- 视觉降级来源符合现有实现；
- 低资源情况下安全降级。

## 8. 保存、失败重试与幂等性

### 8.1 每词保存

对 screening、ordinary review、usage confirmation、visual match 分别模拟：

- 保存成功；
- 第一次失败、第二次成功；
- 连续两次失败；
- 保存过程中重复点击；
- 保存成功后浏览器刷新。

必须满足：

```text
同一个 prepared result
→ 重试时保持完全相同
→ 不重复计数
→ 不重复推进 interval
→ 不重复移动 cursor
→ 不重复显示正式完成
```

### 8.2 最后一项

对探险最后一题和挑战最后一题分别模拟保存失败。

验证：

- session 未提前 completed；
- summary / result 未提前显示；
- 次数未提前增加；
- challenge pending 未出现部分成功；
- 重试成功后只完成一次；
- 再次刷新仍为单次完成。

### 8.3 重复完成

手工触发：

- 双击“下一题”；
- 快速连续点击；
- 保存返回后重复调用处理函数；
- 浏览器前进/后退；
- 已完成页面刷新；
- 已完成后再次从首页进入。

验证：

- completed 不重复；
- attempts 不重复；
- reviewCount 不重复；
- wrongItems 不重复；
- challengeFlagAt 不产生重复记录；
- bestScore 不异常累加；
- 不生成同日第二个正式 session。

## 9. 恢复与日期边界

### 9.1 同日恢复

在以下阶段刷新并重新进入：

- screening 未作答；
- screening 已保存、未点下一题；
- review 普通题未作答；
- usage confirmation 中；
- visualMatch 中；
- challenge 第 1 题；
- challenge 第 9 题；
- challenge 最后一题已保存、结果页未打开。

验证：

- 恢复到正确阶段；
- 题面不变化；
- cursor 不倒退；
- 已保存结果不重算；
- 未保存输入的保留策略与执行卡 2—4 约定一致；
- 不出现空白页或两层反馈。

### 9.2 前一日未完成 session

构造前一日未完成探险：

```text
前一日开始
→ 未完成
→ 次日进入
```

验证正式恢复规则：

- 不静默丢弃；
- 不同时再生成一份当日新计划；
- 完成或明确处理旧 session 后，才能进入新的计划生成逻辑；
- 日期显示和 summary 不混淆；
- 状态更新使用实际完成时间但不破坏原计划日期语义。

### 9.3 次日新计划

完成当日探险和挑战后切换到次日 fixture。

检查：

- 新日可生成新探险；
- 旧 completed session 不被继续；
- 到期日期计算正确；
- challenge 次数归零；
- bestScore 使用新日记录；
- 前一日 challenge pending 按 planner 进入新计划；
- 已被探险处理的 pending 不再次出现。

## 10. 两个孩子隔离

使用完全不同的 fixture 分别测试 sister 和 brother。

至少覆盖：

1. sister 无状态，brother 已完成摸底；
2. sister 有未完成探险，brother 无 session；
3. sister 挑战 2 次锁定，brother 仍可挑战；
4. sister 有 challenge pending，brother 无 pending；
5. 两人同一个 wordKey 具有不同 D/H/F 和 interval；
6. 两人分别发生保存失败；
7. 两人切换后再刷新；
8. 两人都完成当日 session。

必须证明：

- 使用不同 `vocab_adventure_v1_*` key；
- session、cursor、plan、word states、challenge attempts、bestScore、wrongItems 完全隔离；
- UI 切换后不会显示前一位孩子的缓存；
- 全局变量已重置或重新加载；
- TTS、题面和结果页引用当前孩子；
- 旧 daily task 数据兼容层不会把次数串线。

任何串线均为 P0，必须修复后重跑完整隔离矩阵。

## 11. 换设备与跨浏览器验证

### 11.1 目标

验证当前 MVP 使用既有云端 `kv_store` 后，在第二浏览器环境或第二设备能够读取同一孩子的正式状态。

不新增表，不设计新的同步协议。

### 11.2 测试方法

至少使用两种彼此隔离的浏览器环境，例如：

```text
浏览器 Profile A
浏览器 Profile B
```

或：

```text
本地桌面浏览器
本地 iPad / WebKit 模拟环境
```

流程：

```text
A 登录 sister
→ 完成若干题并确认保存成功
→ 关闭 A

B 登录同一 sister
→ 读取相同 session / cursor / word state
→ 继续完成
→ 返回 A 刷新
→ 读取 B 完成后的状态
```

再对 brother 重复最小流程。

检查：

- 不依赖 A 的 localStorage 才能恢复正式学习状态；
- 预览开关本身可以是设备本地设置，但业务 state 不能只存在 localStorage；
- A、B 不同时覆盖旧版本 state；
- 保存时遵循现有版本或最新状态策略；
- 不因旧 batchId/cardIndex 在另一设备失效而串词；
- 完成后两个环境看到一致 summary。

### 11.3 并发边界

MVP 不要求复杂实时协同，但必须测试：

```text
A 与 B 同时打开同一未完成 session
```

最低安全要求：

- 不出现数据结构损坏；
- 后保存不能把 completed 恢复成未完成；
- cursor 不能明显倒退；
- reviewCount / attempts 不应双增；
- 若系统不支持并发答题，应明确阻止或提示刷新；
- 在验收报告中写明当前并发策略和限制。

发现并发问题时，优先做简单、安全的版本检查或 stale-state 防护，不引入复杂实时同步系统。

## 12. 离线只读与恢复联网

### 12.1 定义

本卡所说“离线只读”是：

```text
页面或已加载数据可以被查看
但无法可靠保存时，不允许伪装成正式完成
```

不要求本卡新增完整离线写入队列，也不要求发布新的 Service Worker。

### 12.2 离线进入

在已有页面和必要资源可用的前提下断网。

检查：

- 已保存 summary、词卡或当前题可查看；
- 明确显示无法保存或当前为只读；
- 不允许在无法写入时正式提交答案；
- 不增加 D/H/F；
- 不移动 cursor；
- 不消耗 challenge attempts；
- 不写 challenge pending；
- 不显示“保存成功”。

若资源本身未缓存，允许页面无法重新加载，但必须在报告中明确：

```text
当前 MVP 仅保证已加载页面的离线只读
不保证全新离线启动
```

不得为了通过测试偷偷修改正式 Service Worker 发布策略。

### 12.3 作答时断网

分别在以下时点断网：

- 点击确认前；
- 保存请求进行中；
- 保存失败反馈后；
- 最后一题；
- challenge 完成提交。

验证：

- UI 保留当前题；
- 显示重试；
- prepared result 不变化；
- 恢复联网后重试只保存一次；
- 页面刷新前后不会伪完成；
- 同步成功后状态正确。

## 13. 挑战完整验收

### 13.1 不足 10 个候选词

验证：

- 不创建正式 session；
- 不消耗次数；
- 不复制目标词；
- 提示先完成探险；
- 旧入口次数状态不变化。

### 13.2 第一轮挑战

准备至少 10 个已摸底词。

验证：

```text
10 个不同目标词
→ 10 道无提示题
→ 正式计分
→ 错题列表
→ attempts = 1
→ remaining = 1
→ bestScore 正确
```

检查：

- 目标词、题型、选项确定性；
- 刷新恢复；
- 正确题不改变 interval；
- 错误题只写 challenge pending；
- wrongItems 信息完整。

### 13.3 第二轮挑战

验证：

- attemptIndex 更新；
- 新 seed 可产生新计划；
- 仍为 10 个不同目标词；
- 不覆盖第一轮尚需展示的最终 summary，除非正式设计明确只保留最新一轮；
- attempts = 2；
- remaining = 0；
- bestScore 取两次最高；
- 第三次入口锁定。

### 13.4 新旧入口共用次数

流程：

```text
预览入口完成 1 次
→ 关闭预览
→ 旧挑战入口只剩 1 次
```

以及反向：

```text
旧挑战完成 1 次
→ 开启预览
→ 新挑战入口只剩 1 次
```

必须证明不会出现：

```text
旧入口 2 次 + 新入口 2 次
```

### 13.5 挑战错词回流

准备至少 2 个错词。

检查挑战完成后：

- `challengeFlagAt` 或正式同义字段写入；
- D/H/F 未变化；
- interval 未变化；
- nextDueAt 未被挑战重置；
- reviewCount 未增加；
- 已冻结 plan 不被插题。

生成下一次正式新探险计划，检查：

- challenge pending 优先；
- 同一词不重复；
- plan reason 正确；
- 该词完成探险后 challenge flag 清除；
- 探险 D/H/F 正常更新；
- 若为 F，后续来源为 failed；
- 挑战答对不能清除旧 pending。

## 15. 数据质量与异常状态

### 15.1 失效定位

构造：

- batch 删除或隐藏；
- cardIndex 变化；
- 批次顺序变化；
- 同词存在于多个批次；
- 旧 session 保存旧 `_batchId`；
- 词卡字段局部缺失。

验证：

- 始终优先按 `wordKey` 解析；
- 不串到另一个词；
- 找不到目标词时安全停止；
- 不自动对错误词保存结果；
- 提供可理解的错误或恢复路径；
- 不因一个失效 item 破坏整个 state JSON。

### 15.2 重复词

验证：

- 可见候选池去重规则一致；
- planner 和 challenge 使用相同 wordKey 语义；
- 同一 session 不重复目标词；
- 两个批次中的同词不会各自增加一次状态；
- 显示卡内容使用当前最新可见卡；
- 旧 plan 仍能稳定解析对应词。

### 15.3 字段不足

分别缺少：

- meaning；
- emoji / image；
- phonetic；
- collocation；
- example；
- 可用干扰项。

验证题型可用性和回退，不得生成无法完成的题。

### 15.4 损坏或旧版本 state

对脱敏 fixture 测试：

- 缺字段；
- 多余字段；
- `cursor` 越界；
- completed 与 cursor 不一致；
- challenge session 旧格式；
- 非法 JSON；
- 旧 key 中没有新字段。

要求：

- 使用现有 migration / normalization；
- 能安全读取的尽量兼容；
- 无法安全读取时不覆盖原数据；
- 显示错误并停止正式写入；
- 不把损坏 state 当作全新用户静默重置。

## 19. 缺陷分级、修复和回归

- 最终再运行完整 adventure 测试和旧功能 smoke；
