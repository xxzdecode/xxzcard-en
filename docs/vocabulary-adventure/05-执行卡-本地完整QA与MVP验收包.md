## 3. 设备、并发和用户模型

### 3.1 不要求同一账户多设备并发

本项目实际不会出现 sister 或 brother 在两台设备上同时作答，因此以下内容不是本卡强制完成项：

- 同一账户多设备同时挑战；
- 同一账户的跨设备版本冲突；
- 同一账户 stale-state 竞争；
- 为上述场景开发锁、版本号、事务或复杂并发控制。

禁止为了本卡额外开发同账户多设备并发控制。

### 3.2 仍须验证普通换设备

需要验证但不要求并发：

- 在设备 A 保存后，设备 B 能读取该用户已同步的探险状态；
- 刷新后恢复当前已保存 session、cursor 和题目；
- 未保存的界面瞬时状态不应被误报为已跨设备同步；
- `batchChallenge_*` 的旧本地记录不跨设备同步应作为已知限制展示，不判为缺陷。

### 3.3 两个用户同时挑战是 P0 隔离验收

sister 和 brother 必须能够分别在两个浏览器 context、窗口或设备环境中同时挑战。

必须完全隔离：

- challenge session；
- cursor；
- 题目顺序；
- attempts；
- bestScore；
- wrongItems；
- `challengeFlagAt`；
- 探险 session、plan、word state 和完成状态。

交叉操作至少覆盖：

- 双方交错答题；
- 任意一方先完成；
- 任意一方中途退出；
- 任意一方保存失败并重试；
- 任意一方刷新并恢复；
- 一方切回首页或切换用户；
- 两人命中相同 `wordKey`。

无论操作顺序如何：

- 不得推进另一方 cursor；
- 不得改变另一方题目或题序；
- 不得增加另一方 attempts；
- 不得改写另一方 bestScore 或 wrongItems；
- 不得把一方 `challengeFlagAt` 写到另一方；
- 不得改变另一方探险状态；
- 一方失败不得阻断或回滚另一方。

发现任何串线按 P0 处理，本卡不得通过。

## 4. 正式视口矩阵

本卡正式视口只有：

1. iPhone 16 竖屏；
2. iPad 11 横屏；
3. 一个普通桌面视口，用于旧功能回归。

测试应记录实际 CSS viewport、device scale factor、触控配置和浏览器引擎。若自动化环境没有同名设备描述符，使用最接近的 Playwright 官方设备参数并在验收包中写明实际值。

## 5. iPhone 16 竖屏验收

至少验证：

- 首页“探险 / 挑战”入口完整可见；
- 页面无水平滚动；
- 长单词、长释义和长例句不溢出；
- 选择题按钮不会过窄；
- 拼写输入框和确认按钮可操作；
- 字母排序、句子排序支持换行；
- 软键盘弹出后当前输入框、确认按钮和反馈区仍可操作；
- 顶部进度、题目主体和底部反馈条不重叠；
- 挑战结果和错题列表可以完整滚动；
- 所有核心触控按钮高度至少 44px。

覆盖流程：

- 首页进入探险与挑战；
- 至少一种基础选择题；
- 拼写题；
- 字母排序；
- 句子排序；
- 错题反馈；
- 挑战结果页；
- 刷新恢复。

软键盘验收允许使用真实移动设备人工证据或能可靠改变 visual viewport 的自动化证据；若桌面仿真不能真实弹出软键盘，必须明确标记为待真机验证，不得伪报通过。

## 6. iPad 11 横屏验收

至少验证：

- 探险、抗遗忘和挑战完整流程；
- 顶部进度、主体和底部反馈区无重叠；
- `visualMatch`、选择题、拼写题和排序题均可操作；
- 结果页无水平滚动；
- 核心触控按钮至少 44px；
- sister / brother 切换后异步首页状态正确刷新。

必须覆盖：

- 摸底开始、中途恢复和完成；
- 抗遗忘开始、中途恢复和阶段总结；
- 挑战开始、答题、退出、恢复和结果；
- 保存失败不前进，重试同一 prepared state；
- 切换用户后入口文字、次数、最高分、探险进度均来自当前用户。

## 7. 普通桌面旧功能回归

至少验证预览开关关闭时：

- 旧首页入口和旧挑战默认行为保留；
- 今日、混合、批次挑战次数聚合仍正确；
- 老师端不显示儿童探险入口；
- 单词卡、生词巩固、随堂练习、知识点库等非本功能入口未被隐藏或阻断；
- 页面无新增水平滚动或不可点击遮挡。

桌面视口只承担旧功能回归，不替代移动和平板验收。

## 8. 状态、保存和恢复验收

### 8.1 每词保存与刷新

摸底、抗遗忘和挑战分别验证：

- 保存成功后才前进；
- 保存失败时 cursor 和题目不变；
- 重试复用同一 prepared state；
- 不重复增加 reviewCount、attempts 或分数；
- 刷新后从已保存 cursor 恢复；
- 已完成项不重复写入；
- 结果页刷新不产生第二次完成。

### 8.2 离线边界

验证：

- 只读缓存可展示时，不把旧数据误报为最新云端数据；
- 写入失败有明确提示；
- 写入失败不前进、不吞错、不伪装成功；
- 恢复网络后可重试同一保存；
- 一个用户的离线或保存失败不影响另一个用户。

### 8.3 重复完成

至少覆盖：

- 重复点击确认；
- 保存中的再次点击；
- 结果页重复退出；
- 刷新后再次进入完成页；
- 挑战完成与退出竞争。

最终状态只能计一次。

## 9. 执行卡 4 已知限制的正式表述

- `batchChallenge_*` 仍保存在当前浏览器 localStorage，因此旧批次挑战记录本身不跨设备同步；
- 本项目不支持也不需要同一账户多设备同时挑战；
- sister 和 brother 是独立用户，必须支持分别同时挑战且完全隔离。

以上第一、二项不是本卡缺陷；第三项是本卡 P0 验收条件。

## 10. 自动化测试要求

优先新增独立、可重复的测试，不依赖真实线上数据。

至少补齐：

1. sister / brother 两份持久状态的纯函数隔离测试；
2. 两个 browser context 同时挑战的交错操作测试；
3. 相同 `wordKey` 的 `challengeFlagAt` 隔离测试；
4. 一方保存失败、退出、刷新、完成不影响另一方；
5. iPhone 16 竖屏布局与触控断言；
6. iPad 11 横屏全流程与异步用户切换断言；
7. 普通桌面旧入口回归；
8. 保存失败和重复完成幂等；
9. 换设备顺序读取和刷新恢复。

并发测试必须使用两个独立用户，不能把两个 context 都伪装成同一账户。

布局断言至少包括：

- `scrollWidth <= clientWidth`；
- 关键按钮可见且高度 `>= 44px`；
- 顶部进度、主体、反馈区矩形不重叠；
- 长文本容器没有横向溢出；
- 结果页可滚至最后一个错题和操作按钮。
